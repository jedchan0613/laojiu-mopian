# 老旧默片

## 1. 项目是什么

“老旧默片”是一个个人数字档案网站，用于整理和展示具有个人记忆或时代痕迹的旧资料与旧物。

## 2. 项目目标

- 将适合公开的旧资料和旧物进行分类整理。
- 通过网站集中展示这些资料，方便浏览和回顾。
- 在公开展示与隐私保护之间保持清晰边界。
- 让网站发布内容与本地保存的原始档案相互分离。
- 使用稳定的永久编号和统一的数据规范，方便长期整理、检索与引用。

## 3. 第一版包含什么

第一版计划整理和展示以下内容：

- 老照片。
- 老信用卡和其他卡片。
- 明信片。
- 信件。
- 老证件。
- 老笔记。
- 笔记本。
- 其他旧物。

网站中使用的资料均为从原始档案中筛选出的发布副本，并根据需要进行压缩和脱敏处理。

## 4. 第一版不包含什么

- 不把网站作为高清档案主库。
- 不在网站中保存原始高清扫描件。
- 不在网站中保存未经处理的敏感资料。
- 不用网站代替独立的本地档案系统。
- 不负责管理或备份原始档案。

## 5. 文件夹说明

- `docs/`：保存项目需求、数据规划和开发记录。
- `archive-data/`：保存经过整理、适合网站使用的档案数据，不保存原始敏感资料。
- `public-assets/`：保存经过筛选、压缩和必要脱敏后，可供网站公开展示的素材副本。
- `samples/`：保存用于参考、测试或演示的少量样例资料，不放入真实敏感档案。
- `site/`：Astro 网站程序和网站可读取的发布层数据；不保存档案主文件。
- `local-admin/`：只在本机运行的档案管理入口；草稿与已发布数据分开保存。

## 6. 本地档案管理入口

双击项目根目录的 `启动档案管理.cmd`，即可在浏览器中打开本地档案管理页面。网站预览与管理入口共用 `127.0.0.1:4173`：网站位于 `/`，管理入口位于 `/admin/`。

启动时会自动检查页面是否过期，需要时重新生成并检查后再打开；已有服务时复用4173。开发验收使用的4183等临时地址不作为日常入口。

当前可以：

- 新建和编辑藏品信息。
- 按正式数据规范填写通用字段和对象专属 21 维。
- 上传、预览和调整发布副本顺序。
- 保存未公开草稿。
- 查看发布前预览和缺失项提示。
- 安全替换或移除图片，并从本地回收区恢复。
- 从发布前历史版本恢复为草稿。
- 完成人工隐私检查后正式发布。
- 自动生成网站数据并执行正式构建。

详细说明见 `docs/local-admin-guide.md`。

## 7. 永久编号与数据规范

- 正式永久编号统一使用 `LJM-YYYYMMDD-TYP-NNN`。
- `YYYYMMDD` 是实物进入本人档案系统的接收或获得日期，不是拍摄、书写、签发或邮寄日期。
- `TYP` 使用项目正式对象类型代码；`NNN` 是同一接收日期、同一对象类型下从 `001` 开始的顺序号。
- 永久编号只表达对象身份。分类、年代、地点、人物或研究结论发生变化时，只修改元数据，不修改永久 `item_id`。
- 收藏品编码 `collection_code` 不包含永久编号，只由 Excel 打勾维度中的正式必填属性代码自动生成；它会随属性更新，但不改变单独保存的永久编号。
- 数据分成“通用管理元数据”和“对象专属描述元数据”两层。详细规则见 `docs/data-model.md`、`docs/coding-standard.md`、`docs/metadata-dimensions.md` 和 `docs/code-dictionary.md`。
- 当前规范来源文件是 `docs/reference/archive-metadata-standard-v1.xlsx`。

## 8. 隐私原则

- 原始高清扫描件、敏感资料和原始档案只保存在独立的本地档案系统中。
- 网站只保存经过筛选、压缩和必要脱敏的发布副本。
- 发布前应检查姓名、证件号码、账户信息、地址、联系方式、签名及其他可能识别个人身份的内容。
- 无法确认是否适合公开的资料，默认不发布。
- 网站中的发布副本不能替代原始档案，也不应作为原始档案的唯一备份。

## 9. 正式网址与网页分享信息

网站已经包含标题、简介、分享卡片和搜索引擎基础信息。本地构建不会把 `127.0.0.1` 或 `localhost` 写成正式网址。

以后确定公开域名后，在正式构建环境中设置 `PUBLIC_SITE_URL`，例如 `https://example.com`。届时页面才会自动生成规范网址和带绝对地址的分享图片；在域名未确定前保持为空，避免搜索引擎记录错误地址。

## 10. 联系挂件与纠错入口

公开网站所有页面都有右下角“联系我”挂件，支持合作洽谈、隐私问题和其他事宜。留言通过现有私密收件服务保存，提交成功后提供 `LX-` 联系编号和查询密钥；正文、联系方式和管理记录不会进入公开网站文件或档案数据。

隐私问题可以填写相关档案编号或页面地址，并继续访问 `/corrections/` 纠错与撤下说明页。首次留言不接收附件，并明确提醒不要提交完整证件号码、精确私人地址、清晰签名、医疗资料或未脱敏图片。管理端入口为 `/admin/contacts.html`。

确定真实的公开联系邮箱后，可以在正式构建环境设置 `PUBLIC_CONTACT_EMAIL`。格式有效时，私密联系服务暂不可用的状态下会提供备用邮件入口；未配置时不会显示虚构邮箱。
