# 网站基础产品优化清单

更新时间：2026-08-31

本清单覆盖公开网站首页、档案列表、档案详情和本地档案管理入口。排序依据是：是否阻碍主要任务、影响范围、误操作风险和实现成本。

## 第一优先级：让核心内容和主要操作更早出现（已完成）

主要问题：列表页首屏看不到档案，详情页多图连续堆叠把说明推到很后面，管理页辅助编码说明长期占据主要空间，首页分类入口缺少内容数量提示。

本次已经完成：

- 首页分类显示已公开数量或“待收录”，并在“浏览全部”入口显示总数。
- 档案列表只常显搜索和藏品分类，年代、地点、标签收进“更多筛选”；有筛选时才显示“清除筛选”。
- 档案详情把多张图片改为主图与缩略图切换，并缩短标题、图片、基本信息和说明之间的距离。
- 档案管理把完整编码规则改为按需展开，藏品分类选择在桌面并排显示。
- 公共顶部导航标明当前所在栏目，减少位置判断成本。

## 第二优先级：保持浏览连续性和公开信息层级（已完成）

本次已经完成：

- 档案列表把关键词、分类、年代、地点和标签统一写入页面地址；从详情返回时恢复原筛选结果和原来的浏览位置。
- 详情页增加同一访客分类内的“上一件 / 下一件”，并在继续浏览时保留原筛选条件。
- 年代、地点、人物、故事、流传线索和原文优先展示；内部编号、状态、权限、数字化和备份信息统一收进默认折叠的“研究与管理信息”。
- 已经在故事区展示的原文和流传线索不再在其他分区重复显示。
- 档案管理五个步骤增加实时完成提示：已完成显示“完成”，未完成显示缺失项数量，隐私步骤显示“待确认”。

## 第三优先级：可访问性、性能与细节一致性（已完成）

本次已经完成：

- 公开网站和本地管理端增加“跳到主要内容”，统一清晰的键盘焦点样式，并尊重系统的“减少动态效果”设置。
- 详情图片缩略图和管理端步骤标签支持左右方向键、Home 和 End 键切换；管理端标签使用正式的标签页语义。
- 每次正式构建自动从发布副本生成 320、640、1280 和 1920 像素 WebP 网页副本；原发布图片保持不变，浏览器按屏幕宽度自动选择。
- 本地管理端可为每张发布图片单独维护图片说明；说明会跟随排序和替换，公开页优先使用人工说明，缺失时只使用中性的正面、背面或细节图说明。
- 档案筛选增加可单独移除的条件标签和明确的无结果页面；管理端成功、错误、处理中、记录数量和保存状态统一提供可见及辅助技术提示。
- 当前公开档案只有 4 件，暂不增加排序和分页；避免让简单浏览承担额外操作成本，达到约 20 件后再复评。

## P1 基础体验完善（已完成）

本次已经完成：

- 按页面用途统一有效内容宽度和标题节奏：首页保持较短阅读行宽，档案列表与详情使用更适合图片和资料并排的宽度，关于页保持文章阅读宽度。
- 首页分类入口仍位于首屏，并增加自动生成的“精选档案”和“最近收录”；数据直接来自当前公开档案，不维护第二套首页数据。
- 详情发布图片支持全屏放大、多图前后切换、键盘方向键与关闭键，以及手机左右滑动；只读取网站现有发布副本。
- 档案管理为当前记录增加“下一步”任务提示和基本资料、图片、专属资料、隐私确认四组状态，可直接跳到待处理分区。
- 已发布记录提供对应公开详情的直达入口；没有公开页面或已经撤销的记录只返回网站首页。
- “撤销档案”从主要操作区移入“更多操作”，恢复入口同样按需显示，降低高影响操作的误触风险。
- 详情页按真实内容显示“故事与原文”和“标签”：没有故事、流传线索或原文时不再显示空标题，只有标签时使用独立标签分区。
- 管理端操作按钮随工作区和当前步骤变化：维护概览、草稿、回收区和历史版本不再显示无关的保存、发布按钮；长表单底部持续提供保存状态和快捷保存入口，发布按钮只在“隐私与发布”步骤出现。

## P2 维护效率与质量保障（已完成）

本次已经完成：

- 本地档案管理增加独立的“维护概览”，集中显示需要补充公开简介、图片说明、研究状态、证据等级、权利状态和备份状态的正常档案。
- 左侧概览数量只统计需要日常处理的正常档案；已撤销记录单独说明，只参加完整性核对，不混入补录任务。
- 每条待办按照公开内容、图片说明、研究、权利和备份分组，并提供“打开处理”直达相应档案与填写分区。
- 增加只读完整性巡检，核对正式 JSON、对象类型与 schema、隐私等级、公开详情页、待入站发布图片、公开原尺寸副本、响应式图片清单与副本，以及管理端和公开构建隔离。
- 图片使用校验值逐一比较待入站区、网站发布目录和正式构建目录，巡检只生成结果，不会自动删除、移动、覆盖或修复档案文件。
- “重新检查”只刷新当前报告；发现问题时按资料、图片、网页副本和公开构建分组显示，能够定位到具体档案时提供直达入口。
- 正常档案的“更多操作”增加相似新建，只复用对象类型、批次、获得方式、来源和省市区；永久编号、题名、年代、图片、专属信息、公开文字和隐私确认重新建立。
- 图片进入草稿前先在本机检查格式、大小、危险命名、扩展名与格式是否一致，并使用 SHA-256 校验值识别本次选择及待入站区中的完全重复文件。
- “复盘日期”未安排、格式异常或已经到期时进入维护概览；界面明确建议每次复核后把下一次日期安排在未来 12 个月内，不根据文件修改时间推测。
- 公开页面补充 Open Graph、分享卡片、页面类型和搜索简介；只有配置正式 `PUBLIC_SITE_URL` 后才生成规范网址与绝对分享图片，避免把本机地址公开。
- 增加公开站点 `robots.txt`；正式域名未确定前不生成可能错误的站点地图地址。
- 档案详情页增加“复制页面链接”和“复制规范引用”，引用内容包含题名、永久编号、网站名称、页面地址和访问日期。
- 档案列表增加“最近收录、年代从早到晚、年代从晚到早、按藏品类型”四种排序；排序与搜索、分类、年代、地点、标签可以同时保留在网址中。
- 每件公开档案生成 `CreativeWork` 结构化信息；没有正式域名时不写入本机网址，配置 `PUBLIC_SITE_URL` 后自动补齐正式页面和图片地址。
- 正式构建增加条件式站点地图与固定公开页面回归检查；首页重复、详情空区块、图片尺寸缺失或管理内容混入公开目录时会阻止构建完成。
- 管理端增加可选的“公开修订说明”；详情页只在有实质修订说明时展示，没有内容时不生成空区块。

## 下一阶段产品建议

建议按以下顺序继续，暂不在本阶段提前实现：

1. **内容编辑质量**：逐步补充人工图片说明、来源叙述和不确定性标记，并增加字数、重复内容和空泛标题提示；提示只辅助人工判断，不自动改写正式资料。
2. **隐私确认改为逐项主动确认**：每次正式发布默认不勾选，避免把“已阅读”变成无意识的默认状态；服务器的 13 项完整校验继续保留。
3. **纠错与撤下渠道**：公开网站确定实际联系方式后，在关于页增加纠错、权利补充、限制公开和撤下申请说明。
4. **正式域名收尾**：域名确定后只需配置 `PUBLIC_SITE_URL`；分享图片、规范网址、结构化页面地址和站点地图会在正式构建中自动生成。
5. **公开内容关联浏览**：当公开档案达到约 20 件后，再增加相关档案、时间线和地点入口；达到约 50 件后再评估排序与分页。

## 当前结论

网站目前没有需要更换框架或引入数据库才能解决的基础问题。前三个公开体验优先级、P1 基础体验和 P2 维护保障均已通过现有 Astro 静态网站和纯本地管理入口完成；同批次录入、图片预检、复核提醒和公开页面元信息也已补齐。下一步应优先处理内容质量和隐私主动确认，而不是继续增加复杂浏览功能。
