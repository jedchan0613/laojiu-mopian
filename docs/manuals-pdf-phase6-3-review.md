# 说明书PDF6.3：整册生成与预览

日期：2026年11月12日。范围：用户明确要求“执行6.3”。

本地PDF草稿已支持受限逐页生成、整册完成后更新预览、本人只读阅读、进度回执、停止和明确重试。仅使用虚构账号与合成PDF验收，没有真实说明书入站、送审、公开发布或线上部署。6.4 PDF送审与版本审核尚未实施。

## 怎样使用

1. 双击根目录的`启动档案管理.cmd`，进入“说明书 → 提供说明书”，或从“我的 → 我的投稿 → 继续编辑”重开原草稿。已有旧启动窗口时，先保存其他工作、关闭原窗口，再重新启动，避免仍使用旧程序。本轮未启停日常4173服务。
2. 按[6.2操作说明](manuals-pdf-phase6-2-review.md)私密保存一份筛选过的PDF。在文件区下方找到“生成整册预览”。
3. 选择“标准清晰”或“精细核对”，点击“生成整册预览”。标准长边最高2400像素；精细最高4096像素，同时受800万像素限制。每个环境一次处理一册，同账号只能有一册处理或排队。
4. 页面显示等待、检查和逐页进度。可以离开页面后回来查看，请保持本地启动窗口运行。处理中暂时锁定本册文字和文件替换；仍能打开上一次完整预览。
5. 全部页面成功后显示“已完成的整册预览”，点击“预览整册”，使用“上一页／下一页”、页序选择和“原尺寸查看／适宽查看”。图像放大后在图片区域内滚动。每页标明源PDF页码，不提供拆页、换序、删页或图片编辑。
6. 逐页核对文字、图表、方向、裁切和缺页。字体未嵌入或生成工具提示会明确保留，不能因为有预览就认定内容完全正确。
7. 结果暂时不明时点击“核对生成回执”。页面先找原任务，不因响应丢失重新建册。需要停止时点击“停止本次生成”；确认停止或失败后，可点击“重新生成整册”。
8. 替换PDF会保留旧文件和旧预览，并提示旧预览尚未对应当前PDF。新整册全部完成后才一起切换。PDF仍不能下载或提交审核，下一项6.4另行实施。

## 结果留存与故障

| 情况 | 实际行为 |
| --- | --- |
| 生成中 | 新页只在私密任务内保存；旧阅读器不会出现半册 |
| 完整成功 | 核对全部页序、文件大小、摘要、源文件和草稿版号，再一次切换整册记录 |
| 中途失败、停止、超时 | 保留旧完整预览、源PDF和已生成JPEG；不会自动重跑 |
| 替换PDF或配置变化 | 旧预览可读并显示来源／配置提示；新任务重新绑定源摘要与版号 |
| 接收响应丢失 | 按同一操作凭证查询回执，成功结果直接找回；重复请求返回原任务 |
| 服务异常退出 | 核对原进程及受限环境结束后标为中断，由用户明确重试；进程身份不明时停在待维护者核对 |
| 完整页已保存、草稿切换失败 | 保留完整页图并标“需维护者核对”，不覆盖旧版、不自动重试或清理 |
| 草稿已切换、最终回执写入失败 | 根据草稿的任务绑定找回成功结果，不重复生成 |
| 记录回退或页图被改动 | 拒绝错误结果，显示待核对；不能用取消删除完整结果 |

本阶段会在受限进程确定结束后清理本任务的临时输入副本和工具输出`.part`。清理对象是可重建的处理临时文件；完整上传PDF、已生成JPEG及旧版均保留。保留副本持续占用容量，停止或失败不会免费腾出空间。

## 边界与容量

| 项目 | 当前限制 |
| --- | --- |
| PDF源文件 | 沿用6.2：20 MiB，每册最多5份不同PDF |
| 成册页数 | 1—200页；201页整份拒绝，不截取前200页 |
| 页面 | 单张JPEG最多5 MiB、800万像素；先核对全部页面尺寸和旋转，再按固定配置生成 |
| 每册图片 | 所有旧版、部分结果与孤立JPEG合计100 MiB、1000份；不按当前预览页数免费重算 |
| 生成记录 | 每册最多200次；达到上限保留原结果并拒绝新增 |
| 账号／服务 | 沿用200 MiB／默认10 GiB；源PDF、JPEG、历史、孤立文件、临时字节和未使用预留统一统计 |
| 并发 | 单环境一个执行器、最多10册等待；单账号一个未完成任务 |
| 时间 | 信息检查每步10秒、转图每页30秒、整册最多20分钟 |
| 资源 | 子进程及任务512 MiB硬限制；诊断每次及累计有64 KiB边界；渲染字节最多5 MiB |
| 异常结构 | 加密、脚本、交互表单／签名结构、嵌入附件、无法核对的页数／尺寸停止处理 |

图片写入、普通投稿和PDF使用相同容量锁。逐页新增前先预留空间，临时字节与未使用预留只计一次。小型管理JSON和锁标记不计入既有文件载荷额度，但任务、源文件和草稿均有数量上限。

## 本地工具与维护

没有安装新Node包、数据库驱动或云服务。复用6.1已确认的Poppler固定候选包`26.09.0-0`、项目已有Sharp图片处理能力，以及Windows自带的.NET C#编译器。固定版本便于复验，不表示已确认它是当前最新版本。

`local-admin/native/ManualPdfSandbox.cs`在本机编译成专用小执行器，编译缓存与配置放在Git忽略的`local-admin/pdf-runtime/`；工具仍位于Git忽略的6.1候选目录，不进入网站或系统PATH。首次编译会有少量启动等待；无编译器、工具缺失、摘要不符或程序已更新未重启时，暂停新生成，已有文件和预览仍保留。迁移电脑、升级工具和服务器适配需要重新验证，不会自动安装或下载工具。

当前私密配置`local-admin/pdf-runtime/local.json`只允许`schema`、`enabled`和绝对`tool_directory`。本机已指向原6.1候选目录。关闭`enabled`后暂停新生成；查看已有预览、查询与停止仍可使用。服务生产模式同时拒绝PDF上传和生成，本轮没有开放服务器能力。

执行边界：原PDF仅由受信任服务复制到当前任务的只读输入；每个任务创建Windows AppContainer（系统隔离身份）且网络能力为零，执行时检查真实子进程身份。工具、当前输入和输出目录仅给读取／执行权限，转图器不能直接写文件；输出经有大小限制的管道交回服务，由服务验证JPEG并保存。Job Object（系统进程组）约束内存、超时、取消和子进程树。任务结束后收回该任务权限及系统隔离身份；不能证明安全结束时保持待核对，不按裸PID误杀其他进程。

每次生成核对固定包全部561个文件的大小和摘要，并绑定处理程序、清晰度和Sharp配置摘要。接口不接受工具路径或任意命令。干净的子进程环境不继承账号／邮件密钥，账号页面不返回原始诊断、绝对路径、工具配置或进程号。页面是私密处理结果，生成不会自动遮盖图像里的信息。
