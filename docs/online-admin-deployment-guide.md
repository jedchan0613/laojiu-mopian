## 两个包分别包含什么

管理程序包包含：

- 档案管理服务、Cloudflare Access 验证和线上版本切换程序。
- 管理页面。
- Astro 网站源文件、当前公开发布副本和现有依赖清单。
- systemd 管理服务模板。
- 不含真实邮箱、团队域名和 AUD 的配置示例。

管理程序包不包含：

- `node_modules`、旧构建结果和可重新生成的响应式图片。
- 草稿、历史版本、回收区和私有数据包内容。
- Cloudflare 密钥、登录密码或真实管理员邮箱配置。

初始私有数据包包含 68 个源文件，加上 1 份包内校验清单。逐文件与本机数据比较结果为：缺失 0、多余 0、内容变化 0。

## 上线后的发布方式

在线维护仍遵循原有 13 项人工隐私确认。检查和网站构建全部成功后，程序会：

1. 在 `/srv/laojiumopian/releases/` 中创建一个新的独立公开版本。
2. 确认新版本包含首页、404、`robots.txt` 和站点地图。
3. 把所有公开目录设为可读、不可由访客写入，并拒绝构建结果中的软链接。
4. 最后一次性切换 `live` 软链接，让 Caddy 开始读取新版本。
5. 保留原公开版本，不自动删除，便于必要时回退。

如果构建、复制或软链接切换任一步失败，新版本不会生效；程序会恢复管理数据和应用内发布源，当前公开网站继续使用旧版本。

## 线上图片批次限制

单张图片仍不得超过 30 MB。线上模式一次保存最多携带约 60 MB 新图片；超过时页面会要求先保存草稿，再继续选择下一批。这是为了给 Cloudflare 请求体限制和 JSON 图片编码留出安全余量，不改变“只能上传经过筛选、压缩和必要脱敏的发布副本”这一规则。

## Ubuntu Snap Node 服务路径

服务器交互终端可以使用 `/snap/bin/node`，但 systemd 加固服务不能通过需要额外能力的 `snap-confine` 启动器运行。服务应直接使用 `/snap/node/current/bin/node`，npm 应使用 `/snap/node/current/bin/npm`，并把 `/snap/node/current/bin` 放在服务 `PATH` 最前面。该方式继续使用服务器已经安装的同一份 Node.js，不需要开放额外系统能力，也不需要降低 `NoNewPrivileges` 等安全限制。

## 下一阶段顺序

下一阶段将逐条完成以下操作，每完成一小步就检查结果：

1. 把两个批准的 ZIP 上传到服务器的 `/home/ubuntu/laojiumopian-upload/`。
2. 在服务器重新计算 SHA-256，与本手册数值比较。
3. 把程序解压为一个新的应用版本，把私有数据解压到已经建立的数据目录。
4. 再次核对所有目录所有者和权限。
5. 使用 `package-lock.json` 安装网站现有依赖并进行第一次服务器构建。
6. 建立只允许管理服务写入新公开版本的权限和 `live` 软链接。
7. 填写 Cloudflare 团队域名、应用 AUD 和唯一允许登录的邮箱。
8. 安装并启动 systemd 管理服务，但先只做服务器本机检查。
9. 把 Caddy 的公开根目录切换到 `releases/live`，验证首页内容没有变化。
10. 最后通过 `https://admin.laojiumopian.com/admin/` 验证登录、拒绝未授权访问和只读功能；通过前不进行真实发布操作。
