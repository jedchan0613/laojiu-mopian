# 2026-09-26 网站现状评估与档案字段精简结果

本次基于公开页面、本地档案维护界面、实际数据和正式规范表重新检查。档案字段精简先按用户授权完成；随后用户明确要求按本文件执行第1项网站优化，已完成适用于当前规模的设计、内容、交互与加载优化。检查对象为本地预览，没有线上部署或真实投稿、联系操作。

## 网站设计、功能和性能建议（实施前评估）

现有暖纸色、中文衬线字、朱红点缀和档案展签已形成统一风格，适合私人档案馆。接下来应提高内容质量、浏览效率和细节一致性，无须重新搭建网站或增加复杂系统。

| 优先级 | 实施前问题与依据 | 原建议 |
| --- | --- | --- |
| 优先处理 | 纸纹颗粒在实际页面中仍较抢眼，细字和照片周围容易显得灰、旧、杂。 | 降低纸纹强度，适当提亮底色，保留衬线字和朱红主识别。让图像成为视觉重点。 |
| 优先处理 | 320×760手机档案列表中，第一张图片约在纵向723px才出现；筛选和说明占用较多空间。现有窄屏已无横向溢出。 | 手机端收起“按线索浏览”，合并重复搜索提示，优先让访客看见第一件藏品。无需重做已修好的窄屏溢出和标题换行。 |
| 优先处理 | 6件公开档案中3件没有独立公开简介；13张图片均未填写自定义图片说明。现有替代说明并非空白，但依赖题名和文件名推断图像角色。 | 补充简短、可靠的简介与正面/背面/细节说明。只描述能确认的画面，不推断真实人物身份，不自动编造史实。内容完善比继续增加装饰更能提高可信度。 |
| 优先处理 | 规范表明信片PC11“通信关系/关联机构”、PC18“邮票”标为必填；当前发布规则配置缺少这两组。 | 按正式规范核对这两组的填写、未知与不适用要求，再统一维护页提示和发布检查。字段规范来源为 `docs/reference/archive-metadata-standard-v1.xlsx`，本次没有调整这项既有差异。 |
| 第二批 | 首页选读与类型/年代入口存在部分重复，暂时无内容的分类仍会引向空结果页。 | 精简重复引导，对空分类清楚标注整理状态；精选内容优先使用有完整简介和图像说明的档案。保持克制，避免为了填满页面而增加重复藏品。 |
| 第二批 | 首页主字体约687KB，比单张首页图片的12–33KB明显大；已具备预加载、替代字体显示和缺字检查。此前也已评估过本机字库处理条件。 | 后续具备稳定处理条件时，评估小型常用界面字库与扩展字库按需加载，保留全站字形覆盖检查；先比较实际下载量和维护成本，不直接替换成更大的外部字库。参考[字体加载优化指南](https://web.dev/articles/optimize-webfont-loading)。 |
| 第二批 | “关联地点：中国”对两件照片的推荐关系过弱；详情中相关档案入口和部分内部备份信息也增加了阅读干扰。 | 同城、具体题材、明确组合关系优先于同属一个国家；合并重复相关入口，公开页淡化内部维护状态。 |
| 第二批 | 首页轮播圆点使用tab语义，但方向键未切换选中项。详情大图目前主要是适应窗口，读小字、邮戳时缺少真正放大与拖动。 | 补齐轮播键盘行为或采用更合适的按钮语义；如确有读图需求，为现有安全发布副本增加放大和拖动。参考[WAI标签页键盘规则](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)。不得为放大效果公开原始扫描主档。 |
| 随数据增长再做 | 公开档案列表先渲染全部卡片和检索内容，再隐藏分页外项目；每次输入遍历、排序和高亮全部记录。当前仅6件，未观察到可证明的严重卡顿。 | 等规模达到数百件或实测出现卡顿后，再增加输入合并、分批呈现和检索优化。当前无需新框架、数据库或在线搜索服务。 |

现有搜索匹配、无结果提示、轮播点击和主要页面的窄屏布局已检查正常。不把已有修复重复列为当前缺陷；字体和大量档案下的性能建议也不等同于已测得的线上加载故障。

| 对应建议 | 已完成的处理 |

| 手机目录首屏 | 年代与地点入口在手机默认收起，桌面默认展开；搜索全宽，分类与排序并列，合并重复提示。320×760预览中第一张图片从约723px提前至513px，提前约210px。 |
| 公开简介与图片说明 | 补齐3件缺失简介，为现有13张图片补齐逐图说明；纠正仅根据文件名误判的背面提示，明信片可明确区分留言面和风景面。保留原题名与已有描述、原文、标签，不推断身份或编造史实。 |
| 明信片必填规则 | 按Excel核对并恢复PC11、PC18必填组与PC18邮票图案／版别字段；维护提示和正式发布检查使用同一规则。两组没有对应字典代码，不补造编码。3件原记录缺项以“未知”暂记，仍需后续研究；不是把未知判断为不适用。 |
| 首页引导与精选 | 去掉重复选读标签，尚无内容的分类显示为“正在整理”的普通文字，不再进入空结果；精选优先选简介与逐图说明完整的档案，同等完整时优先最近收录，并继续排除上下区重复藏品。 |
| 字体加载 | 使用本机已有处理能力把同源字体拆为常用约133KB和扩展约119KB，按页面文字加载，保留授权、系统替代字体和全站缺字检查。实测首页仅下载常用字库，相比原主字库约687KB减少约81%；没有外部字体请求或新增依赖。原字库保留为维护来源。 |
| 相关档案与内部状态 | 明确关联、相册／系列、标签与具体地点优先；不再仅因同属中国或同一省份推荐。去掉访客页内部备份状态，减轻基本信息中的重复跳转文案。 |
| 轮播与读图 | 轮播圆点改为按钮语义，支持左右方向键、Home和End。详情安全发布副本支持100%至400%放大、拖动、滚轮、双击、键盘调整和适应窗口；换图自动复位，关闭后焦点回到原按钮。未引入原始扫描主档。 |
| 大规模检索 | 维持原建议的条件：当前只有6件公开档案，未观察到严重卡顿，不提前新增框架、数据库或在线搜索。达到数百件或实测卡顿时再做分批呈现。 |

6件公开档案的修改前数据及13张既有发布图片已在本地历史区备份。永久编号、自动收藏品编码、图片路径、隐私等级和发布状态均不变；原始档案主库、现有草稿和撤销记录未改动。历史版本只允许按原规则恢复为草稿，不直接重新公开。

## 档案维护字段处理结果（已执行）

| 字段类别 | 处理方式 | 保留原则 |
| --- | --- | --- |
| 藏品分类、题名、显示年代、入藏日期、批次编号、物理位置 | 六项常用信息直接填写 | 编号所需日期和批次不隐藏、不混淆。 |
| 永久编号、收藏品编码 | 合并为紧凑只读信息条 | 永久编号不变，收藏品编码仍自动计算。 |
| 获得方式、来源名称、来源地点、流传说明、综合备注 | 移入补充分组 | 保留独立存储和不同含义。来源日期不自动等同入藏日期。 |
| 年代范围、尺寸、载体、研究、备份和利用记录 | 沿用集中分组，完成的组默认折叠 | 尚未完成的必填组自动展开，仍按原要求检查。 |
| 相册、系列、原始位置、关联档案等低频候选项 | 组合要求已被批次满足时隐藏空项 | 已有值进入“已保存的扩展字段”；组合要求未满足时保留入口。 |
| 人物、机构、附件关联编号和地点代码 | 专属页面末尾集中为选填区 | 可继续添加和维护，数组仍为数组。必填项不会移入纯可选区。 |
| 公开简介 | 默认直接填写 | 优先完成访客阅读内容。 |
| 公开原文、标签、修订说明 | 合并为“公开文字补充”折叠区 | 信件原文仍直接显示；新建档案暂不展示修订说明。 |
| 历史邮局字段、旧格式人物编号和证据说明等 | 保留旧值查看与维护入口 | 折叠和隐藏不会使保存丢失旧值。 |
| 原文转录与公开转录、正式主题代码与公开标签 | 没有自动合并数据 | 用途不同，不能简单互相覆盖；公开文字继续受隐私检查约束。 |

本次没有物理删除规范字段或档案内容。对于“看起来重复、但含义不同”的信息，采用界面集中和按需展开；对于已经自动生成的内容，取消大面积只读表单占位。
