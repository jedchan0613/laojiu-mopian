## 一、核对方式

对照原方案第二部分的 A–N 节，逐项核对四个阶段的实现；同时审查了安全（重定向、验证码存储、会话存储、越权）、边界（并发、重复点击、配额）、异常处理与用户体验。

## 二、发现的问题与处理

| # | 问题 | 方案依据 | 严重度 | 处理 |
| --- | --- | --- | --- | --- |
| 1 | **账号级配额完全缺失**：任何账号可以无限建草稿、无限提交、无限占用存储 | K 节"增加账号级配额…不能反复删除重传来绕过" | 高（防滥用） | ✅ 已实现（见下） |
| 2 | **注销、导出等敏感操作没有近期重新验证**，只要求有效会话 | D.7"换邮箱、注销、导出等敏感操作需近期重新验证" | 中（安全） | ✅ 已实现（30 分钟会话窗口） |
| 3 | **换邮箱没有"收不到原邮箱验证码"的出路**，用户会被卡死 | D.8"收不到原邮箱验证码时进入人工恢复流程" | 中（流程） | ✅ 已加人工恢复提示 |
| 4 | 新加文案含未覆盖汉字"尝"，构建检查失败 | 构建的字库覆盖检查 | 低 | ✅ 改措辞避开 |

### 修复 1：账号级配额（方案 K）

按方案拆成三个独立维度，各自在正确的时机生效：

- **同时保存的未提交草稿 ≤ 20 件**：在"保存草稿"时检查；
- **每天提交审核 ≤ 10 件**：在"提交审核"时按当天动作统计（创建草稿本身不计）；
- **账号未公开资料占用 ≤ 200 MB**：在增删图片（创建、保存、提交）时检查；草稿、投稿与历史版本都计入，已停止处理的不计，防止靠删除重传绕过。

超限返回明确原因（"未提交的草稿已达上限""今天提交审核的次数已达上限""资料占用已达上限"），且互不影响其他账号。

### 修复 2：敏感操作近期重新验证（方案 D.7）

`resolveSession` 现在返回会话创建时间；`createRequest`（注销、导出申请）要求会话在 **30 分钟内**创建，否则提示"请先退出并重新登录"。防止被借用的长期会话被滥用。

### 修复 3：邮箱恢复提示（方案 D.8）

账户设置的"更换邮箱"区新增提示：如果原邮箱已无法收到验证码，请通过联系入口告知站主，人工核实身份后协助恢复，不要凭猜测反复提交。

## 三、审查后确认无问题的关键项

| 安全 / 功能点 | 结论 |
| --- | --- |
| 登录跳转 `next` 参数 | 只允许站内路径（`/` 开头且非 `//`），无开放重定向 |
| 验证码存储 | 盐 + SHA-256 哈希 + `timingSafeEqual`，不可逆，绑定邮箱/目的/事务 |
| 会话 token | 仅存哈希，可撤销；闲置 7 天 / 最长 30 天 |
| 越权防护 | 不属于当前账号的投稿/图片/申请统一返回 404，不泄漏编号是否存在 |
| 投稿人详情 | 已剥离管理员内部备注、`key_hash`、内部历史 |
| 收藏 | 上限、去重、已撤下档案显示"暂不可查看"且不展示缓存图片 |
| 旧投稿关联 | 账号 + 原编号 + 原密钥三重校验 + 明确确认 |
| 通知 | 只在用户开启偏好时发送，邮件不含图片/正文/联系方式 |
| 头像 | 用文字印记，不开放图片上传（页面已说明） |
| 版本与并发 | 只读版本、修订号乐观锁、重复点击/重试不产生重复投稿 |
| 撤回/停止处理 | 已收到的停止处理申请阻止发布；已转草稿沿用现有机制 |

## 五、未做 / 已知限制

- **管理端"邮箱恢复核实"专门功能**（方案 H）：需要站主人工核实身份后代为处理邮箱变更，涉及信任流程，工作量大，建议上线后按需补。
- **`notifyPublished` 遍历全部投稿**：投稿量小（上限 2000），每次发布约几百毫秒，影响可控；量大时可加 `linked_item_id` 索引。
- **服务端错误的逐字段定位**（方案 L）：客户端已用 HTML5 校验定位到字段；服务端校验错误目前用通用提示，可在后续把错误信息结构化（含字段名）后逐字段标红。
- **阶段四的实际上线**：未执行（等你预览确认并单独授权）。
