# 老旧默片中英文网站建设方案

版本：V1.0｜日期：2026年10月14日｜用途：产品与开发实施方案

## 1. 建议与目标

采用“一个网站、一套档案事实、中文和英文两种展示”的方案：默认简体中文，提供 English 切换；导航、档案列表、档案详情、搜索筛选、收藏以及访客操作提示共同切换。中文继续作为现有档案的主要维护语言，原始资料则保留自身语言。

推荐沿用现有 Astro 静态网站及腾讯服务器部署方式，利用框架已有的多语言路由能力和轻量文案字典完成改造。第一版不需要购买第二个域名，也不需要引入新的数据库、CMS 或第三方翻译插件。翻译结果提前整理、审核和保存，再随网站构建发布。

**实施状态：用户批准后已于 2026 年 10 月 14 日完成双语改造及正式上线。下文保留方案设计，实际完成内容、使用方法和验收结果见 [双语网站使用与验收记录](bilingual-site-review.md)。**

## 2. 已核对的基础与实施前提

本次只读检查了实际项目 `C:/Users/35171/Documents/BaiduSyncdisk/laojiu-mopian` 的配置、档案模型、展示入口、页面、管理生成流程及发布检查，并参考了官方多语言文档。

| 已核对情况 | 对方案的影响 |
|---|---|
| 当前站点为 Astro 静态网站，现有依赖只有 Astro | 可以继续静态生成中英文页面，控制维护成本 |
| 永久 `item_id`、类型代码、分类代码已经独立存在 | 两种语言共用同一个档案身份及统计数据 |
| 档案使用 `core`、`metadata`、`public_view` 三层结构 | 保持原结构，新增展示翻译层，不复制另一套业务事实 |
| `archive-view.ts` 集中处理档案展示和搜索字段 | 可以在这一入口统一选择语言，避免各页面分别拼装 |
| `archive.ts` 由档案管理程序重新生成 | 英文不能直接手工写进这个生成文件，否则后续维护会丢失 |
| 题名、字段标签、代码标签、年代地点、图片说明及不少交互提示目前固定为中文 | 需要同时改页面和交互脚本，不能只改导航 |
| 地点、标签筛选当前使用原始文字值 | 应保持内部筛选值，翻译仅影响显示标签 |

**实施前必须先核对线上最新版本。** 本次本地生成档案文件包含78条公开记录；近期“维护作品档案”聊天的发布结果曾报告108条公开记录。两者属于不同快照，108不能作为本次实时核验的线上数量。在线访问工具未能连通网站，本次没有连接生产服务器。因此，正式开发与发布必须先取得服务器当前发布快照，核对档案编号清单、源码版本和最近维护内容，避免旧本地数据覆盖已经更新的线上档案。

实施时以线上正在使用的最新发布数据作为存量翻译清单；草稿、非公开档案及内部管理备注继续沿用原有权限。

## 3. 访客看到的语言切换

### 3.1 入口与默认规则

桌面端在主导航右侧设置 `简体中文 | English`；手机端放在菜单内的固定位置。选项用语言名称，不用国旗代替语言。当前语言有明确状态，键盘和屏幕阅读器可以操作。

| 场景 | 预期行为 |
|---|---|
| 打开现有中文首页或中文链接 | 显示简体中文 |
| 点击 English | 打开当前页面对应的英文版本 |
| 在英文版继续浏览、刷新页面 | 保持英文 |
| 在档案详情切换语言 | 保持同一档案编号，不跳回首页 |
| 分享或收藏英文页面地址 | 接收者打开即为英文 |
| 浏览器本身使用英语 | 不自动改变默认简体中文规则 |
| 关闭浏览器后重新打开已收藏的英文链接 | 仍为英文 |

**语言以网址为准。** 浏览器可以记录上次选择，用于提示“继续浏览英文版”；直接打开中文或英文链接时，以该链接的语言为准。第一版不增加跨设备语言偏好同步。这样，默认中文、明确链接和浏览器记忆之间不会发生反复跳转。

### 3.2 网址安排

中文保留全部现有网址，英文使用 `/en/` 前缀：

| 页面 | 中文 | 英文 |
|---|---|---|
| 首页 | `/` | `/en/` |
| 档案列表 | `/archive/` | `/en/archive/` |
| 同一条档案详情 | `/archive/{item_id}/` | `/en/archive/{item_id}/` |
| 关于 | `/about/` | `/en/about/` |
| 投稿 | `/contribute/` | `/en/contribute/` |
| 纠错与撤下 | `/corrections/` | `/en/corrections/` |
| 登录、收藏与个人中心 | 现有 `/login/`、`/me/...` | 对应 `/en/login/`、`/en/me/...` |

上表中的英文地址已按方案创建。中文旧链接继续有效。语言切换同时保留搜索词、分类、年代、地点、标签、排序、分页及必要的页面锚点；不擅自翻译访客输入的搜索词。

原图、图片下载地址、接口地址与资源地址仍使用现有共用路径；不能对所有 URL 简单加 `/en/`。

## 4. 哪些档案信息跟着切换

### 4.1 三类内容分别处理

| 内容 | 处理方式 |
|---|---|
| 导航、按钮、页面标题、提示、报错、空状态、字段名称 | 从统一的中英文界面字典读取 |
| 档案题名、简介、年代文字、地点显示名、人物机构说明、标签、更多信息、图片说明、修订说明 | 保存对应的英文展示文本，切换时读取 |
| 档案编号、类型与分类代码、年份范围、尺寸数值、图片、相册关联、收藏和点赞 | 共用原有数据；格式可随语言调整，事实与身份不变 |

各类型的专属信息也要覆盖，包括照片、明信片、信件、日记笔记、证件、卡片及其他实际公开的类型。代码对应的中文标签和英文标签来自同一个代码，不另外发明分类编码。维度名称同样提供英文显示名。

代码字典与字段规则继续以现有规范为准；英文标签放在展示字典中，不改写原有 Excel 规范和已使用代码的含义。

### 4.2 原文与译文

原始影像、手写文字转录、邮戳原文、原件题记保留其原始语言，可能是中文、日文、英文或其他语言。切换网站语言不会改变图片内部的文字。

英文详情页建议提供：

- `English translation`：经过核对的英文译文。
- `View original text`：查看原文，标注原始语言。
- 原件对照：译文、原文与发布图片保持对应关系。

原始文本本身已经是英文时，无需另造英文译文。只有摘要翻译时，应标为 `English summary`，不能当作全文翻译。逐张图片的英文说明按稳定图片路径或图片标识关联，避免调整图片顺序后正面、背面和说明错配。

### 4.3 术语与历史不确定性

建立小型术语表，至少覆盖藏品类型、专属维度、年代说法、地名、人名拼写、纸张与保存状态、权利与下载说明。

| 中文表达 | 英文示例 | 要求 |
|---|---|---|
| 明信片 | Postcard | 全站统一 |
| 约1960年 | c. 1960 | 保留“约”的含义 |
| 20世纪80年代 | 1980s | 不变成确定拍摄年份 |
| 年代未知 | Date unknown | 不从接收日期推断年代 |
| 地点待考 | Location unconfirmed | 保留待考状态 |
| 不适用 | Not applicable | 与未知区分 |
| 正面 / 背面 | Front / Back | 与实际图片一致 |

示例属于展示文案建议，不新增业务代码。“未知”“未记录”“待考证”根据原字段含义分别处理，不统一填成空白。人物姓名采用已有可靠译名或一致的转写方式；无法确定读音时保留原文，避免编造拼写。历史地名保留历史语境，需要现代地名说明时以既有考证依据为准。

版权和下载文案保持原意，英文切换不得改变下载许可。翻译不得新增历史事实，也不得扩大原有公开信息范围。

### 4.4 品牌表达

保留“老旧默片”现有标识与视觉风格。英文页可增加 `Laojiu Mopian`，副标题建议为 `An Archive of Everyday Lives`。这是候选文案，实施时统一确认。中文页使用中文内容，英文页使用英文内容，品牌名和必要原文除外。

## 5. 档案翻译的长期维护

### 5.1 一条档案，共用事实

继续保留现有 `core`、`metadata`、`public_view`。新增按 `item_id` 关联的翻译记录，只保存可公开字段的英文文本及译文状态，不再录入一套年份、尺寸、分类或权限数据。

建议翻译工作记录位于独立维护目录，例如 `archive-data/translations/{item_id}/en.json`；目录位置在实施时按现有发布流程确定。维护记录不能直接整体放进公开目录。构建时只输出“审核通过、来源仍匹配、允许公开”的译文。

基本机制：

1. 每项译文关联其来源字段，例如 `core.title`、`public_view.description` 或某个专属维度字段。
2. 保存来源字段的内容指纹，用来识别该字段是否已更新。
3. 中文修改后，只把受影响的英文项标记“需复核”，不因无关字段更新作废全部译文。
4. 旧译文作为历史保存；未经复核，不继续作为当前有效英文公开。
5. 人工修改的英文记录不会被重新生成中文档案文件覆盖。
6. 多值字段保持数组，并逐项对应来源；图片说明以稳定资源标识关联。

### 5.2 管理端的使用方式

现有管理入口继续用中文，增加“英文内容”面板：左侧来源内容，右侧英文文本；显示未翻译、待审核、已审核及需复核状态。提供预览、保存草稿、核对变更和随档案发布等操作。

| 状态 | 含义 | 访客页面 |
|---|---|---|
| 未翻译 | 没有英文文本 | 提示翻译尚未完成 |
| 翻译草稿 | 已有初稿 | 不公开草稿 |
| 待审核 | 等待事实及表达核对 | 不作为有效英文公开 |
| 已审核 | 来源匹配且审核通过 | 可随发布流程公开 |
| 需复核 | 来源字段已修改 | 停用受影响的旧译文，显示明确回退 |

记录审核人、审核时间、来源版本和修改历史；这些管理信息不进入公开搜索索引。中文档案的正常发布不必因为英文未完成而阻塞，但需要列出待翻译项。

### 5.3 翻译流程与成本

来源核对 → 术语统一 → 英文初稿 → 事实与措辞复核 → 双语预览 → 随现有构建发布。

AI 可以协助产生初稿，输入范围限于已确认可公开的文字；正式译文需要核对事实与不确定性。可先人工或离线批量准备译文，不必第一版就接入付费翻译服务。

访客打开网页时读取已保存译文，不临时调用翻译服务。主要长期成本是新增与修改档案的翻译、校对工作，以及约增加一份页面文字的构建产物；图片继续共用。实施前统计实际公开字数、长篇转录和术语覆盖情况，再估算工期与翻译费用。

### 5.4 缺少英文时

保留同一档案的英文页面入口，使用明确英文提示，例如 `English translation pending`，并允许查看标有来源语言的原文。不能把中文静默呈现成已经完成的英语内容，也不能显示已过期的旧译文。

第一版正式上线要求：全站核心界面完成英文；全部拟上线档案的题名、类型、年代显示、地点显示、简介及图片说明完成英文核对；所有已显示的专属字段有英文标签，内容完成翻译或按明确的原文规则呈现。长篇原文的全文译文可以分批上线，但必须说明完成情况。

英文尚未达到基本内容门槛的详情页，暂不加入英文搜索引擎收录清单；通过 `noindex` 明确处理，中文页面正常收录。达标后再加入对应语言关联。

## 6. 搜索、筛选、收藏与交互

### 6.1 双语搜索

构建一个按永久编号合并的公开双语检索索引，覆盖已公开的中文、有效英文、原文与审核通过的检索别名。输入 `珠海` 或 `Zhuhai` 可以找到同一组相关档案；英文界面输入中文也能检索，重复命中只算一条档案。

延续现有字段权重与排序规则，第一版在两种语言中使用同一套匹配逻辑，保证切换时结果数量、顺序和分页稳定。匹配提示用当前界面语言；查不到时提供当前语言的提示与清空条件入口。

检索索引只包含当前已公开、允许检索的字段。未审核译文、被撤下档案、内部备注、私密投稿和原始主档路径不进入索引。

### 6.2 筛选与关联

分类、年代、地点、标签保留原有内部筛选值；显示标签随语言改变。例如内部仍使用原地点键，英文选项显示 `Zhuhai`，不要把英文显示名写回分类数据。

切换后分类数量、相册关系、同类推荐及上一件/下一件关系一致。数字日期和档案编号继续用于共用排序。第一版不新增按英文题名排序，以免语言切换改变既有排列。

### 6.3 收藏、浏览足迹与点赞

收藏和点赞继续按原 `item_id` 记录，中英页面共享同一状态与计数；不创建“英文收藏副本”。

当前浏览足迹会缓存题名、类型、年代与图片说明。改造时应以编号从当前语言的公开摘要重新获取显示文字；旧缓存做兼容处理，已撤下档案不继续从旧缓存显示。公开摘要需包含语言信息，并使用独立语言地址，例如规划中的 `/en/records.json`。

### 6.4 表单、账号与联系

登录、注册、收藏操作、投稿、联系挂件、纠错申请及个人中心的成功、失败、处理中、空列表状态都应翻译。

接口继续共用现有 `/api/...`；由稳定错误码或状态码映射成当前语言，不让服务返回的中文错误直接出现在英文页面。服务端日志和内部管理界面可以继续中文。

登录后的返回地址、联系挂件识别的档案地址、筛选返回链接均需支持 `/en/`，并维持原有安全校验，防止外部跳转。

完整英文访客闭环还应覆盖验证、通知等现有邮件模板：只为账号业务增加语言偏好，不能混进档案元数据；邮件回跳链接使用对应语言，既有账号没有设置时默认中文。访客提交的留言、投稿和纠错正文按原样保留，不因界面切换自动改写。

## 7. 搜索引擎、分享与页面表现

采用独立语言网址，使英文页面可被直接访问、分享和收录。Google 的官方指南建议不同语言使用不同网址，并提供可点击的语言切换入口。[Google 多语言网站指南](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)

具体安排：

- 中文与英文公开页分别使用自己的规范网址；通过 `hreflang` 互相声明对应关系，不能把全部英文规范网址指向中文页。[Google 本地化页面说明](https://developers.google.com/search/docs/specialty/international/localized-versions)
- HTML 正确声明简体中文或英文，原文片段单独声明语言。语言标签按用途区分：HTML 可以使用 `zh-Hans`/`en`；搜索语言关联采用受支持的 `zh` 或 `zh-CN` 与 `en`；分享平台使用其支持的 locale 格式。[W3C 页面语言声明](https://www.w3.org/International/questions/qa-html-language-declarations)
- 页面题名、描述、分享摘要、结构化数据和图片说明随语言输出。
- 站点地图排除根路径和 `/en/` 下的登录、个人中心、错误页及未达标英文页；这些账号页的 `noindex` 规则同步保留。
- 新旧 URL 均需核对，英文版不造成现有中文链接失效。

视觉沿用当前纸张底色、照片和档案馆气质。针对英文调整字体回退、行距和换行；在手机上检查长题名、长地名、表单提示及导航，不用缩小到难以阅读的字号解决溢出。语言切换后直接进入对应的静态页面，避免先显示中文再替换英文的闪烁。

## 8. 分阶段实施与交付

以下阶段是一个整体改造计划；每阶段有可检查结果，工期在取得线上基线和字数清单后确认。

| 阶段 | 工作 | 完成标志 |
|---|---|---|
| 1. 基线与内容清单 | 同步最新发布快照；核对代码、公开编号、图片、权限；整理界面及字段清单、术语表 | 可追溯的版本基线、翻译清单和回滚版本 |
| 2. 双语基础与样板 | 公共语言字典、路由、链接；集中展示层；选择跨类型、原文多语种、未知年代地点等代表性样板 | 同一档案可完整切换，缺译与长文本规则可演示 |
| 3. 存量与维护流程 | 批量整理最新公开档案译文；增加英文维护面板、审核状态、来源变化检测和双语预览 | 翻译不会被下次录入覆盖，核心内容达标 |
| 4. 全站访客闭环 | 双语检索、收藏足迹、表单、账号提示、邮件、分享和收录规则 | 英文访客能够完成既有全部主要操作 |
| 5. 验收与正式发布 | 正式构建、移动端检查、公开内容检查、服务器路由缓存核对、发布与回滚核验 | 新旧链接正常，档案数量及权限与基线一致 |

第一版交付物包括：中英文页面、公开字段翻译字典、存量译文、术语表、英文维护入口、过期译文提示、验收记录和简短使用说明。中文档案内容的历史维护记录继续保留。

## 9. 验收标准

验收覆盖全部公开页面和已开放访客功能；档案内容先全量自动核对，再按类型人工抽查。

| 类别 | 必须通过 |
|---|---|
| 默认与直达 | 中文旧链接默认简中，英文深链接直达英文；刷新及前进后退正确 |
| 当前档案 | 任意详情页切换后仍是同一个永久编号 |
| 界面覆盖 | 导航、按钮、表单、错误、空状态、图片说明、分享文案均按当前语言显示 |
| 内容覆盖 | 核心档案内容达到上线门槛，所有可见专属字段有英文标签和明确内容策略 |
| 原文 | 译文不会覆盖原件文字；摘要与全文译文清楚区分 |
| 事实一致 | 年份范围、尺寸、证据状态、权利状态、图片及关联关系一致 |
| 搜索筛选 | 中英文别名命中同一编号；切换前后搜索词、筛选、数量、顺序及分页保持 |
| 收藏足迹 | 收藏和点赞共享；英文页不出现旧缓存中文题名或已撤下内容 |
| 维护更新 | 修改任一已翻译来源字段后，对应英文标为需复核；旧英文不会继续有效公开 |
| 图片变更 | 调整、替换或移除图片后，说明仍对应正确资源 |
| 发布检查 | 中英文 HTML、摘要 JSON、索引、分享数据均执行公开字段和权限检查 |
| 私密边界 | 英文页面和索引不能额外包含非公开档案、未审核译文、管理备注及主档路径 |
| 账号入口 | 两种语言的登录及个人中心均 `noindex`，不进入站点地图 |
| 移动与可访问 | 手机无横向溢出，长标题可读；键盘可操作，页面和原文语言声明正确 |
| 正式发布 | 沿用正式 build 全流程；服务器英文路由、资源、接口、缓存与回滚检查通过 |
| 数据基线 | 中文公开编号与图片清单没有遗漏；英文编号与基线一致，缺译状态清单可核对 |

维护侧译文记录的简化结构示意如下；这是设计示例，不是已经保存的真实档案内容：

```json
{
  "item_id": "LJM-20260808-PCD-001",
  "locale": "en",
  "fields": {
    "core.title": {
      "text": "New Year Greetings at the Foot of Mount Fuji",
      "source_hash": "<来源字段内容指纹>",
      "status": "draft"
    },
    "public_view.description": {
      "text": "<经核对的英文简介>",
      "source_hash": "<来源字段内容指纹>",
      "status": "draft"
    }
  }
}
```

字段路径必须来自公开字段白名单，不能接受任意路径。审核人、审核时间和历史记录在维护侧补充；公共输出只包含有效展示值，不包含这份记录的管理信息。具体字段名在实施阶段与现有校验规范统一。

技术依据：[Astro 原生多语言路由](https://docs.astro.build/en/guides/internationalization/)。采用其默认语言不加前缀的方式，中文旧路径继续可用，英文使用单独语言目录。
