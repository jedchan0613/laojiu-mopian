# 前三阶段复查与第四阶段验收

日期：2026-10-18。用户授权复查修复 KIMI 的第三阶段及前两阶段，并执行剩余阶段；随后明确允许无重大阻断时正常上线。本文记录开发验收，实际部署见第五阶段记录。

## 结论

总体符合原方案：完善现有电脑网页版，共用 `/admin/`、同一套元数据、草稿与发布流程；不另建手机系统、不新增依赖。KIMI 的方向与既有第三阶段记录基本一致，但其“测试通过”不足以证明保存和中断行为完全可靠。本轮找到并修复下列问题，原始代码快照保留在 `outputs/mobile-maintenance-stage4/before-review/`。

| 问题 | 修复及验证 |
| --- | --- |
| 普通确认框取消返回非空字符串，被当成同意，可能继续切类型或放弃译文 | 普通框只返回布尔值，离开三选才返回三种选项；真实回调测试取消、Esc、同意 |
| 保存快照只记序号，上传等待后才读取文字与图片；新建并发输入时编号可能未回填 | 请求前固定完整记录、图片说明/顺序与版本；旧响应只确认旧快照，补回同一永久编号并保留新输入；切换档案后不回填旧响应 |
| 新建成功但响应丢失后，仍可能保持“新建”状态 | 查询精确子收据，再读对应草稿与当前版本；先回填原编号再恢复编辑，不重复建档 |
| 图片失败后复用失败子编号，无法真正重试；重启暂存可能过期或失联 | 失败终态分配新子编号，成功丢响应沿用有效令牌；查实际文件、有效期与所属父操作，失效图片重新上传 |
| 前台/联网核对失败后可能恢复自动保存，正在保存时核对还可能误判冲突 | 核对须成功后才恢复；登录失效保持停止，新建同样查登录，活动写入期间不抢先核对 |
| 发布成功响应丢失后核对入口无法正确解除停止 | 只按确切子编号核对，比较成功收据与当前版本；成功时只刷新结果，不重新发布 |
| 读取可能越过尚在入队的写入，KIMI 曾记录偶发队列测试失败 | 读取先等写入登记再排队，新增不等待登记的确定性顺序测试 |
| 同名公开图片被外部改变后，失败发布可能污染原图片 | 发布前比对实际字节，同名异内容拒绝覆盖；新副本复制后再次比对，失败保留原公开内容 |
| 状态按钮的 hidden 被通用样式覆盖；浏览器返回只退一条布防记录 | 补隐藏样式与速览重置；确认离开时越过布防记录，取消继续保留当前页 |

## 第四阶段实现

- 手机变更对照按“字段→已发布→本次修改”纵向排列；电脑继续表格。忽略草稿隔离状态等系统字段，避免把必然恢复的状态算成人工修改；图片清单单独对照。
- 13 项隐私检查默认全部未选，移除全选。先保存并生成清单，再逐项人工确认；有缺项时返回待补定位。
- 新增内存中的发布检查凭据，绑定档案、草稿版本、实际图片 SHA256 与顺序。30 分钟过期或服务重启失效；修改后重新核对。没有凭据、旧版本或图片被替换均由服务端阻止。凭据不保存正文或人工隐私资料。
- 正常发布与未知结果核对均显示实际完成结果和公开页入口；之后再次编辑时移除旧成功提示。草稿与公开版本始终分开。
- 保留统一队列、历史、回收、撤销恢复、相册与六语言能力；不绕过原字段/代码/schema/图片/隐私/构建检查，不增加原档删除能力。
- 部署先安全停止管理写入，取得同一数据目录占用后同步与构建；公开网站继续服务旧版。部署单元只额外允许写私密操作收据目录，安装器创建 0700 目录。应用失败恢复旧版本，保留资料和收据。

## 原方案验收映射与边界

A02—A08、A11—A16、A18 已有隔离自动测试及浏览器/正式构建验证；A01 的生产未授权拦截与 Linux 切换见上线记录。A05/A07/A09/A10/A17 仍需实际安卓复验输入法、相册、键盘、锁屏和前后台；不能由电脑视口或虚构网络故障代替。

手机不持久保存档案正文、图片或登录凭证。网页被系统回收/强制关闭后，服务器最后一次确认之后的输入可能丢失；切后台只尽力保存文字，不保证请求完成。遇到“结果未知”先核对，遇到“冲突”保留本页输入，不刷新丢弃或重复新建。
