## 怎样查看

1. 双击项目根目录的 `启动档案管理.cmd`，使用网站与账号服务共用的本机4173入口。
2. 打开 `http://127.0.0.1:4173/manuals/contribute/`，或在说明书栏目中选择“提供说明书”。未登录时，先登录，登录后返回原草稿地址。
3. 填写品牌、明确适用型号等资料，点击“预览当前填写”核对；可以先保存不完整的内容。
4. 点击“保存私密草稿”，看到明确保存成功提示后即可关闭。草稿地址会带上投稿编号，也可以从“我的投稿”重新打开继续编辑。

若旧版管理服务仍在运行，先保存其他页面的工作并关闭原启动窗口，再重新启动，才能使用新接口。独立的 `启动说明书本地预览.cmd` 使用4236端口，只展示栏目样例，没有账号保存能力。

## 本次完成

| 功能 | 实际行为 |
| --- | --- |
| 专用文字表单 | 品牌、物件名称、品类、用途、明确型号数组、语言数组、地区、版本、明确日期、完整程度、缺页、官方来源、资料来源、权利说明、希望提供的方式、人物情况及署名 |
| 不完整草稿 | 未确定的内容可以留空；未知选项、过长内容、错误数据格式和无效日期会明确报错 |
| 账号归属 | 沿用现有登录和会话，只能通过账号接口读取、编辑自己的草稿；不新增数据库或账号体系 |
| 私密保存 | 复用现有私密投稿目录，状态始终为草稿；不写入公开目录、查询索引或正式档案 |
| 继续编辑 | 我的投稿将说明书草稿送回专用表单；旧普通编辑地址会转回专用页面 |
| 填写预览 | 预览本页当前内容，区分未保存填写与已保存版本；不含图片或整册阅读能力 |
| 来源线索 | 保存文字；通过安全地址规则的HTTPS网址才能点击，其他内容只按文字显示并提示；保存时不访问外站 |
| 保存反馈 | 页首及保存按钮旁都有提示；编辑后显示未保存，离开未保存页面前提示 |
| 并发与重试 | 版本冲突时保留本页填写，不覆盖服务器新版；不确定是否保存时锁定同次请求，重试核对，避免重复创建或增加版本 |
| 暂停开关 | 沿用已有投稿写入开关；暂停时已有草稿仍可读，不假报保存成功 |

“已获授权”“希望提供阅读副本”等选项只记录投稿人的说明与意向，不把保存等同于审核、公开许可或开放下载。现有授权确认仍保持未确认。涉及人物与隐私不确定的内容留在私密草稿，不自动发布。

## 保存与权限边界

沿用私密收件区内的 `record.json`，增加 `submission_kind: manual` 与 `manual_metadata`。这是账号投稿业务数据，与正式档案的 `core`、`metadata`、`public_view`、公开说明书目录及项目外主库分开。通用投稿列表所需标题和分类由这些字段生成；“其他”沿用现有投稿分类，不新增正式档案类型代码。

新接口为 `/api/account/manual-drafts` 和 `/api/account/manual-drafts/TG-…`，沿用现有来源校验、专用请求标记、登录会话、私密路径、账号配额和写入锁。请求仅接收当前支持的文字字段，拒绝图片、送审及额外参数。普通编辑、普通送审、管理员初审与转档案流程均不能把本阶段的文字草稿提前公开。

客户端不把填写内容存入浏览器持久存储，不在地址里放表单内容；服务端不向账号详情下发内部备注、指纹或重试收据。公开构建只包含空表单与程序；填写页禁止搜索引擎收录。维护者仍按现有私密收件区权限管理数据，草稿不属于公开发布资料。
