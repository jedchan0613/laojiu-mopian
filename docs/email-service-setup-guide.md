# 邮件服务配置说明（给站主照着做）

编写日期：2026-09-27。适用阶段：上线前准备。
本文件说明"为什么要配、配哪家、每一步怎么做、配完怎么验收"。价格与免费额度以服务商官网为准，本文的数值于 2026-09-27 核实。

---

## 一、为什么必须有它

现在的登录验证码**没有真的发邮件**，而是写进本机文件夹 `local-admin/accounts/mail-outbox/`，只有你自己在这台电脑上能看到。

网站上线后，访客在自己电脑上点"获取验证码"，你无法手动把验证码递给他，所以必须由邮件服务真的把信送到他的邮箱。**线上登录离不开它**；投稿进度通知也用它，但那一项可以关闭，不影响功能。

配置完成后，密钥只放在服务器的私密环境文件里，不会进入代码仓库。

## 二、两条路径，先看域名是否备案

| | A. Resend（海外，推荐先用） | B. 阿里云 / 腾讯云邮件推送（国内） |
| --- | --- | --- |
| 免费额度 | 3000 封/月，每天上限 100 封 | 阿里云：共 2000 封，每天最多免费 200 封 |
| 需要域名备案 | **不需要** | **通常需要**（发信域名需完成 ICP 备案） |
| 需要实名认证 | 不需要 | 需要 |
| 要加的 DNS 记录 | 2 条（SPF、DKIM） | 6 条（验证、SPF、DKIM、DMARC、MX、跟踪） |
| 国内邮箱送达率 | 需要实测（QQ、163、Gmail 重点看） | 通常更稳 |
| 注册门槛 | 邮箱注册即可，无信用卡 | 需实名 + 备案域名 |

**选择原则**：

- 域名在阿里云或腾讯云、且**已完成备案** → 走 B，国内送达更稳；
- 域名**没有备案**（服务器在中国香港的常见情况）→ 走 A，因为 B 基本用不了；
- 拿不准 → 先走 A。它的步骤最少，能最快验证整条链路是否通；将来真有量再换也不影响代码。

两条路径的代码是同一套，切换只需要改服务器配置文件里的三行（通道、接口地址、密钥）。

### 你的情况（2026-09-28 核实）

| 项目 | 你的情况 | 结论 |
| --- | --- | --- |
| 域名注册商 | Cloudflare | — |
| 域名解析在哪管理 | **Cloudflare**（NS 指向 `*.ns.cloudflare.com`，2026-09-28 实测） | 直接用 Resend 的 **Auto configure**，登录 Cloudflare 授权后自动加好记录，**不用手动填** |
| 是否已 ICP 备案 | **没有备案** | 腾讯云/阿里云的邮件推送走不通 → **走路径 A（Resend）** |

之前误记为"解析在腾讯云"；实测确认在 Cloudflare。网站只是托管在腾讯云香港服务器上，与域名解析在哪里是两回事。

**推荐操作**：在 Resend 的 Add domain 页点 **Auto configure** → 登录 Cloudflare → 授权 → 等待 Verified。若自动配置失败，再退到手动方式（去 Cloudflare 控制台手动添加记录，记录值与主机名按 Resend 列出的原样填写）。

## 三、路径 A：Resend 逐步操作

### 第 1 步：注册

1. 打开 `resend.com`，用邮箱注册（不需要信用卡）。
2. 登录后进入控制台。

### 第 2 步：添加并验证域名

1. 左侧找到 **Domains**，点 **Add Domain**。
2. 填入 `laojiumopian.com`（或子域名，例如 `mail.laojiumopian.com`；用子域名更干净，不影响你以后用主域名收发普通邮件）。
3. 页面会列出需要添加的 DNS 记录，通常两条：
   - 一条 **SPF**（TXT 记录，内容形如 `v=spf1 include:...`）
   - 一条或多条 **DKIM**（TXT 记录，内容是一长串字符）
4. **复制这些记录，去腾讯云的域名解析里逐条添加**（具体见下面的操作路径）。
5. 回到 Resend 点 **Verify**。DNS 生效一般 1—10 分钟，偶尔更久；显示 Verified 即成功。

**在腾讯云添加 DNS 记录的操作路径**

1. 登录腾讯云控制台 → 顶部搜索"我的域名"（或进入"域名与网站 → 域名注册"）。
2. 找到 `laojiumopian.com`，点右侧的 **解析**。
3. 点 **添加记录**，按 Resend 给的内容填写：
   - **记录类型**：选 `TXT`
   - **主机记录**：Resend 给的是完整域名时要改写法——
     - 给的是 `laojiumopian.com` → 这里填 `@`
     - 给的是 `resend._domainkey.laojiumopian.com` → 这里填 `resend._domainkey`
     - 给的是 `send.laojiumopian.com` → 这里填 `send`
   - **记录值**：把 Resend 给的那一长串**完整粘贴**进去（不要改动、不要加空格）
   - **线路类型**：默认
   - **TTL**：默认（600 秒）即可
4. 保存。两条（或多条）记录都要加。
5. 不要动原有的 `NS` 记录和其他已有记录。

> 如果你的域名解析里**已经有一条 TXT 类型的 SPF 记录**（记录值以 `v=spf1` 开头），**不要新增第二条**，而要把新内容合并进原来那条（一个域名只允许一条 SPF）。拿不准就把两条内容发我，我告诉你怎么合并。

### 第 3 步：创建密钥

1. 左侧 **API Keys** → **Create API Key**。
2. **Name**：填一个自己认得出来的名字，例如 `laojiumopian-com`。它只是标签，用来和以后可能建的其他密钥区分。
3. **Permission**：**必须手动改成 `Sending access`**。默认显示的 `Full access` 不要用——程序只需要发信，权限越小，万一泄露影响越小。
4. **Domain**：选 `laojiumopian.com`，把密钥限制在这一个域名上；下拉里没有对应选项时保持 All domains 也可以。
5. 点 **Add**。
6. **密钥只显示一次**，立刻复制并存到安全的地方；关闭弹窗后就再也看不到了。

### 第 4 步：把信息给我

你需要提供三项（发件人由你决定，接口地址固定）：

| 项目 | 你要提供的内容 |
| --- | --- |
| 通道 | 告诉我"用 Resend" |
| 接口地址 | 固定为 `https://api.resend.com/emails` |
| 发件人 | 形如 `老旧默片 <no-reply@laojiumopian.com>`（邮箱地址必须是已验证域名下的，前面的显示名随便起） |

**API 密钥不要贴在聊天里。** 拿到密钥后先自己妥善保存；阶段四部署时我会写好服务器配置文件的模板，由你在服务器上自己把密钥填进去，我不需要看到密钥内容。

代码侧无需改动：项目里的正式邮件通道本来就是按"服务商 HTTPS 接口 + `fetch`"设计的，请求格式与 Resend 完全一致，填入这三个值即可启用。

### 第 5 步：验收（先自测，再由我确认）

**本机自检工具（推荐先自己跑一次）**

拿到密钥后，不用启动网站就能发一封测试邮件：

1. 新建文件 `local-admin/accounts/mail.env`，内容两行（这个目录已在 `.gitignore` 里忽略，不会进代码仓库）：
   ```
   LJM_MAIL_API_KEY=re_你的密钥
   LJM_MAIL_FROM=老旧默片 <no-reply@laojiumopian.com>
   ```
2. 在项目根目录执行（把邮箱换成你自己的）：
   ```
   node local-admin/mail-test.mjs 你的邮箱@qq.com
   ```
3. 收到就说明通道可用；收不到会打印原因，最常见的是「域名还没 Verified」或「密钥权限没选 Sending access」。

> 这封测试邮件里的验证码是假的，不能用于登录，只用来确认能否送达。

**我会做的确认**

1. 用真实流程发一封登录验证码到你的 QQ 与 163 邮箱，确认能收到、不被判为垃圾邮件、发件人显示正确；
2. 走一遍完整的「获取验证码 → 登录」流程；
3. 把结果如实记进开发日志，包括送达失败的情况。

如果 QQ 或 163 收不到，我会调整发件人名称、正文措辞与域名记录再试；实在不行就换服务商。

## 四、路径 B：阿里云邮件推送（仅在域名已备案时）

1. 用已实名的阿里云账号开通"邮件推送 DirectMail"。
2. 控制台 → **发信域名** → 新建域名（建议用子域名，例如 `mail.laojiumopian.com`）。
3. 按控制台给出的 **6 条 DNS 记录**逐条添加到域名解析后台，回到控制台点刷新验证。
4. 控制台 → **发信地址** → 新建发信地址（例如 `no-reply@mail.laojiumopian.com`），并设置 SMTP 密码。
5. 把接口地址、发信地址、密钥给我（同样**不要贴在聊天里**）。

腾讯云"邮件推送 SES"的流程类似，二选一即可。

## 五、你的操作清单（照这个顺序做）

1. 打开 `resend.com` 注册（邮箱注册即可，不用信用卡）。

如果 Auto configure 卡住或授权失败，再退到手动方式：在 Resend 那页切到 **Manual setup**，把它列出的记录原样抄到 **Cloudflare 控制台 → 对应域名 → DNS 记录**里（主机记录按它给的填，记录值完整粘贴），再点验证。卡住时把那一屏截图发我。

## 六、本机测试的环境限制（重要）

这台电脑**直连不了境外接口**（DNS 能解析，但 TCP 连接超时），需要经本机代理才能访问 Resend。而 Node 自带的请求**不会自动使用系统代理**，所以本机直接跑测试会报"邮件服务暂时无法连接：TimeoutError"。

处理办法（已内置在自检工具里）：

1. 确认本机代理端口。可在浏览器能正常打开 `resend.com` 的前提下，用下面这条命令找出代理端口（把结果里列出的端口逐个试）：
   ```
   node -e "const net=require('net');const check=p=>new Promise(r=>{const s=net.connect({host:'127.0.0.1',port:p});s.setTimeout(1200);s.on('connect',()=>{s.destroy();r(p)});s.on('timeout',()=>{s.destroy();r(null)});s.on('error',()=>r(null))});(async()=>{const ps=[7890,7891,7897,1080,1081,8888,8080,10809,15236];const r=await Promise.all(ps.map(check));console.log('在监听的端口:',r.filter(Boolean).join(', ')||'（未发现）')})()"
   ```
2. 在 `local-admin/accounts/mail.env` 里加一行（端口换成实际值）：
   ```
   LJM_MAIL_PROXY=http://127.0.0.1:15236
   ```
3. 加了这一行之后，自检工具会改用 `curl` 经该代理发送，测试即可正常进行。

**服务器上不需要这一行**：中国香港服务器直连境外接口正常，只需填密钥、发件人与接口地址。

> 2026-09-28 实测记录：本机直连 `api.resend.com` 超时；经本机代理 `127.0.0.1:15236` 可正常访问（HTTP 200），并成功发出一封测试邮件。

## 七、常见疑问

**Q：可以先不配吗？**
可以。本地测试完全不受影响；只是线上登录在配好之前不可用（界面会明确显示"登录服务暂时不可用"，不会假装成功）。

**Q：会不会花很多钱？**
按每月几百封估算，两条路径的免费额度都够用；超出后按量计费，单价很低（Resend 超出约 0.9 元/千封，阿里云约 2 元/千封）。以官网为准。

**Q：密钥泄露了会怎样？**
别人可以用你的域名发信，影响发信信誉。所以要放在服务器私密环境文件里（权限仅本人可读），不进代码仓库；如果怀疑泄露，在服务商控制台删掉再建一个即可。

**Q：能用自己的个人邮箱发验证码吗？**
不推荐。送达率差、容易被风控，也容易把个人邮箱搭进去。只作为万不得已的应急手段。
