## 功能与控制

1. 选择恰好两件正式档案，搜索、类型过滤、翻页时保留已选项目。仅 ACT/G/U3 且无草稿的记录可选。检查编号一致、同类型及schema、组合归属、现有必填和收藏编码、待入站图片路径/文件签名/大小/摘要；主档路径不读取，未知结构或新字段没有策略时阻断比较。
2. 86项通用字段逐一配置策略；额外处理收藏编码、全部5项公开字段和当前对象适用的专属维度。不平铺其他schema。基本信息与专属维度旧值未统一时先阻断，避免静默遗漏。代码使用现有字典；缺失、null、0、false、未知代码分别展示。系统字段锁定；单值、人数、尺寸、时间不自动求和或取极值；遮盖字段不提供并集。
3. 并排展示主从现值、字段规则和拟采用值；不同值默认待选，标签可取去重并集。可选择主值、从值、按依据重写，数组字段保留数组。自定义代码、日期和非负整数均校验；人工选主件须记录理由。同源依据不能由“相似”自动确认。
4. 稳定图片引用包含来源编号、文件名和SHA-256。重复摘要仅提示，不删图；支持拖动、上下按钮排序、图注编辑、不采用原因及恢复。图注随图移动。保存时计算目标文件名映射，尚不复制、改名或移走任何文件；转录需按最终图片页序另行核对。
5. 只读关联清单包括其他档案结构化引用、实物相册、标签归集线索、账号收藏、投稿权属、五语言私密及导出译文、既有合并链、匿名点赞。只输出数量和内容摘要，不输出账号姓名/邮箱或译文全文。数量相同但实际引用或译文改变也会使方案失效。
6. 本机未连接线上点赞库时明确“未知”，不填0；当前本机不存在账号库时不创建库，也不据此断言线上无收藏。未接入的借阅、审批、保管期限、密级显示“未接入／不适用”，站外引用显示人工核对。仍可保存待处理方案，**这不是执行前置校验通过**；任何结果的 `canExecute` 均为false。
7. 方案绑定服务端取得的本机维护身份，客户端不能指定操作者或任意磁盘路径。私密目录先加入Git忽略，拒绝链接目录、路径越界和异常文件；方案与不可变旧版本分别保存，使用原有写入队列和操作收据，不增加数据库。
8. 保存核对双方正式版本、图片摘要、引用明细和标准摘要，以及方案自己的版本。旧方案不能直接保存成已复核；重新核对会保留人工文字，变化的来源选值回到待选状态。两个页面冲突时保留当前编辑，明确核对最新方案版本后追加新版。
9. 网络中断或响应缺失时保留编辑和原操作编号，可查询该操作对应的不可变方案版本；不盲目重发另一份创建请求。普通操作收据仍只保存白名单摘要，不写信件全文。磁盘部分写入失败交给既有 `needs_review` 门禁，不假报成功、不删除失败证据。
10. 方案始终标记 `plan-only`、`privacyReviewCompleted:false`。未完成字段、来源依据和引用检查可作为待办保存；不替所有人勾选13项、不复用旧的图片公开批准作为合成图文批准。

## 本机接口

| 接口 | 用途及约束 |
|---|---|
| POST `/api/merge-preflight` | 仅收 `itemIds:[两个编号]`；返回双方快照、字段、图片、引用、阻断/提醒和基础摘要；须同源请求标记，仅读取 |
| POST `/api/merge-plan` | 收主从编号、双方版本、基础摘要、字段选值、图片顺序/图注/不采用理由、同源及主件理由；编辑另带planId/planRevision；使用既有operation/step请求头 |
| GET `/api/merge-plans` | 当前维护身份的方案摘要；前端检索、分批展示，不返回他人方案 |
| GET `/api/merge-plans/:planId` | 原方案及当前检查；基础变化时保留原内容并明确stale |
| GET `/api/merge-plans/by-operation/:operationId/:stepId` | 找回当时保存版本，不能用新版冒充旧请求结果 |
| POST `/api/merge` 等执行接口 | 本机501未开放；线上所有合并路由404，不触发档案写入 |

方案存储：私密 `merges/plans/` 当前版、`merges/versions/` 不可变版本、`merges/plan-operations/` 操作去向。沿用原有原子写入和私密权限；不在公开根目录保存，暂不自动清理。
