受限启动适配、账号完整流程、跨平台审核、异常回收以及**合成数据**的备份恢复已经实现并验证。用户已批准正式安装、一次性受限备份和PDF关闭状态部署。正式处理服务现已安装，并以正式路径的新指纹通过5项原生、36项接口及生产证明门禁验收；真实备份已逐文件核对并合并保存，账号及投稿的隔离恢复检查通过；代码已按PDF关闭状态部署并通过线上核对。外网PDF演练和最终开放仍另行确认。不能把本文当成6.6正式上线完成，也不需要用户自行编写或执行技术验收程序。

## 已实现的处理边界

- 账号进程按系统选择运行器：Windows沿用6.1—6.5的本地隔离；Linux仅连接root持有的Unix通道。公开网页不能指定程序、参数、服务器文件路径或处理地址。
- 通道只接受状态、打开字节快照、检查、顺序转图、关闭、取消及恢复。输入上限20 MiB、单张JPEG上限5 MiB、协议头64 KiB；一个环境同时处理一册，最多8个控制连接。断开连接立即回收本任务。
- 特权通道服务仅存储并核对字节、启动固定任务和签名，不解析PDF或解码JPEG。其正式配置为128 MiB、CPU50%、16个任务、无网络、仅CAP_CHOWN能力；这与单PDF任务的512 MiB是两个不同限额。
- 每册由systemd启动独立任务组，再用Bubblewrap限定文件、进程、网络等可见范围。解析和图片解码最终均以UID/GID65534运行，有效能力及边界能力为0，NoNewPrivs=1。只读挂载工具、字体、固定代码、现有Sharp依赖和本任务输入；不挂载业务数据、账号环境、签名密钥或通道。输出通过有界管道返回，工作进程不能写服务器输出目录。
- 每册整组内存536870912字节、交换0、CPU50%、32个任务、最长20分钟；整个检查回复限10秒、单页限30秒、累计诊断64 KiB。服务退出会停止关联任务，停止时检查整组进程确已结束，再移除本任务临时源。
- 工具、动态库、Node、现有Sharp依赖、字体、字体配置及缓存、链接去向、目录成员和全部运行器代码纳入固定清单。版本或清单变化会暂停能力，需要重新验收；不会自动采用未核对的新版本。

依赖全部复用现有安装。服务器复制的Sharp闭包为0.35.5及其5个既有依赖，许可证文件随副本保留。正式固定版本工具仍以先前已批准的Ubuntu清单为准，未把Windows工具包复制到Linux。

## 来源签名与本地审核

Linux完成整册并确认清理后，用root私密的Ed25519密钥签署源PDF摘要／大小、任务、处理配置、检查报告以及每页JPEG的顺序、大小、摘要和尺寸。账号端再次验证，全部一致才切换旧预览。正常关闭的回复丢失时可从原回执找回；不重复生成。

签名及完整报告只保存在私密任务／提交快照，不进入本人版本摘要或公开目录。签名仅证明生成来源，**不替代逐页核对、提供范围、权利、隐私或21项人工审核**。

Windows离线整理Linux生成的资料时，维护者须先从已核对的服务器安装记录取得公开验证密钥及当前允许的配置指纹，写入被Git忽略的`local-admin/pdf-runtime/trusted-linux.json`。不能从投稿内容自动信任密钥，也不能用本轮合成实验密钥充当生产密钥。

```json
{
  "schema": 1,
  "servers": [{
    "key_id": "已核对的公开密钥摘要",
    "public_key": "已核对的SPKI公开密钥Base64",
    "engine_fingerprints": ["本次已验收且仍允许审核的配置指纹"]
  }]
}
```

这是格式说明，不是可直接采用的配置。配置更新时须同步核对允许列表，不能默默累加旧指纹。能连接当前Linux运行器时以当前配置为准，旧离线列表不能绕过更新；未知、撤销或不匹配的签名会暂停新送审和通过审核。历史版本仍按原快照和实际源／图摘要只读核对，不自动重新生成或扩大公开范围。

## 容量与故障处理

Root私密源副本也计入账号／全局预算：原上传文件、账号临时副本、处理服务临时副本及图片／缓冲预算都要有位置。不能把额外副本藏在账号统计之外。处理服务另外要求至少1 GiB磁盘余量，闭合回执达5000份后暂停接收并提示维护，不自动删除记录。

连接、取消或回收结果不明时保留文件和容量，标记待核对。仅对明确记录为“Linux清理待确认”、尚未进入整册提交的失败任务，在服务恢复且原任务回执再次确认整组结束后，释放预留并标记中断；不会自动重跑。提交中或其他未知状态继续保留人工停止点。恢复旧备份也不重放生成／发布，不覆盖已有预览、快照或来源。

临时回执采用随机临时文件后原子替换，避免进程在写入期间退出后固定临时名阻止恢复。回收应答还核对任务、源摘要和处理指纹，不能用另一任务的应答释放容量。

## 真实Linux合成验收

实验代码最终放在root独占的`/var/lib/ljm-pdf66-bridge-20261112/`。最初候选位于业务账号可改写的上级目录，安装前检查正确拒绝；只移动实验副本到可信路径，没有修改现有应用目录权限。普通账号Rootless Bubblewrap仍按既有规则受限，没有放宽系统策略。

使用现有`ljmadmin`身份及与正式账号服务相同的NoNewPrivileges、只读系统、私密临时区、控制组保护、768 MiB／150% CPU／64任务限制，在独立绑定目录和端口运行账号流程。邮箱仅使用`example.invalid`和本地文件投递；不读真实账号、投稿或邮件内容。

验收覆盖：

1. 真实二进制上传、12页标准及精细转图、提交、21项人工门禁、本人页面摘要、他人／未登录拒绝及源PDF无下载路径。
2. 200页完整生成，200张实际图片摘要、大小、像素页标、顺序及签名全部匹配；精细配置仍受800万像素约束。
3. 201页、加密、限制、脚本、附件、表单、超大版面、损坏和零页拒绝；中文、旋转、裁切、扫描、批注、嵌入及缺失字体样例检查；失败后账号仍能使用。
4. 已接收任务的HTTP回复丢失后按回执找回，处理中关闭PDF仍能取消；关闭后真实图片上传继续可用。
5. 20 MiB文件实际上传与生成成功，20 MiB加1字节拒绝；包含额外服务器副本的预算不足时，在转图前拒绝。
6. 在实际固定启动函数创建的命名空间内复查：输入可读但不可写、引擎和依赖不可写、合成哨兵／账号环境／处理通道／签名密钥／宿主PID不可见；只有HOME、LANG、PATH三个环境键。自建本机监听器前后两次控制连接成功，隔离中连接失败。内核实际读取内存512 MiB、交换0、CPU50%、32任务。
7. 账号进程SIGKILL后，全部处理回收；停止写入后复制完整SQLite主文件及WAL/SHM（存在时）、投稿源、页图、快照、回执和锁记录，逐文件核对摘要、大小、属主、权限和时间，在另一目录恢复。原登录、旧整册、提交版本和两份源保留，中断任务不续发，随后新上传和生成可用。
8. 处理服务SIGKILL后，关联的4个进程全部结束，服务恢复；原账号仍有效，旧预览及快照不变，确认清理后容量归零，没有自动重跑。
9. 单独备份并恢复处理服务私密状态：50份文件（包含合成签名密钥及回执）的字节、权限和属主一致，处理配置指纹保持，恢复后的完整账号流程继续通过。实验私钥未传回本机。

最终数据、时间、检查数及指纹以本轮证据汇总为准。工具层上轮的39,481,605字节裸转图，与本轮经Sharp再编码的47,511,214字节整册是不同产物，不能混用。原生和接口模拟测试分别记录，不把模拟执行器当成Linux隔离证据。
