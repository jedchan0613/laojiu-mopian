# 网站前五项问题优化完善方案

日期：2026-10-18。状态：①②安全、③缓存、④加载及⑤相册状态技术修正已按用户后续授权上线，程序版本 `6a7bdca`；⑤逐字段清单、506个字段建议及4份相册编辑文案仍待用户人工审核和真实发布。上线结果见 `docs/website-foundation-release-20261018.md`。各批验收分别见 `docs/website-security-phase1-review-20261018.md`、`docs/website-cache-phase2-review-20261018.md`、`docs/website-performance-phase3-review-20261018.md`、`docs/website-translations-phase4-review-20261018.md`。

用户先要求“五点全部执行完再统一上线”，后明确“直接部署上线”，并要求继续完成部署。本次依最新授权发布已验收程序并应用缓存，不把待审译文视为已批准；保留全部人工内容审核与隐私门禁。

## 一、范围与执行原则

这里的“前五项”按上次回复的汇总表计算：①图片处理安全，②详情页文字数据转义，③缓存，④加载性能，⑤外语内容待复核。不是体检报告正文的章节编号；备份恢复与安卓真机验收不纳入本次整改范围，但本次上线仍须有自己的回退准备。

目标：先补安全防护，再解决旧页面与加载负担，最后逐项处理失效译文。保留现有Astro、静态网站、账号与管理入口，不增加框架、数据库、云服务、翻译服务或新的直接开发依赖。

共同边界：

- 不改永久编号、分类代码、隐私和发布规则，不修改项目外主档，不把本机档案上传覆盖生产。
- 保留首页“每类一件、只用首图、手动切换”、上下去重、独立相册入口以及逐件计数规则。
- 每批独立修改、测试、记录和验收；一批结束后停止，不自动进入下一批。
- 方案确认不等于实施或上线授权。涉及依赖更新的具体版本、程序上线、Caddy配置变更、译文审核发布分别说明；未经批准不暂停投稿、改开关或更改公开内容。
- 下列体积、版本和122页待复核数量来自2026-10-18体检快照。实施前重新取同口径基线，不把旧快照当实时状态。

## 三、第1项：图片处理安全

### 准备怎么改

1. 在进入图片解码器之前，统一检查实际字节是否为允许的JPEG、PNG、WebP，并核对扩展名及上传类型；不能只检查文件名。文件签名检查是前置筛选，不代替后面的安全解码和完整性检查。
2. 在图片处理入口明确阻止本项目不接收的AVIF/HEIF、SVG等解码器。保留现有大小、像素、张数、动画/多页限制和重新导出安全副本的流程，不扩大接收格式。
3. 统一覆盖免注册投稿、账号投稿（含草稿编辑/补充图片）、管理员上传和网站响应式图片生成。管理员原有文件签名保护继续保留，不为复用代码而降级。
4. 只更新现有依赖树。当前候选为同一7.2补丁线的Astro 7.2.10及Sharp 0.35.5；这是待兼容性验证的候选，不是已经决定安装的版本。已知图片告警的安全下限不能低于Astro 7.2.8、Sharp 0.35.5；其余受影响间接依赖也须重新审计。
5. 保持Sharp作为既有依赖树中的库，不为锁版本随意添加第二份图片库。若现有依赖约束无法得到安全版本，先报告兼容性和维护成本，再确定替代版本；不使用`npm audit fix --force`。
6. 锁文件与安装结果一致，验证实际运行的Sharp及附带原生库，不只查看`package.json`版本范围。用生产现有Node版本和本机环境分别验收，不借机更换运行平台。

预计涉及：`local-admin/submissions.mjs`、现有管理员图片校验、`site/scripts/generate-responsive-images.mjs`、图片安全共用工具及相应测试、`site/package.json`和锁文件。具体共用位置在实现前确定，不复制出多套相互不一致的规则。

### 怎么证明修好

- 合成JPEG、PNG、WebP正常接收；伪装扩展名、伪造类型、损坏/截断、超大和动画/多页文件明确拒绝。
- 用可记录调用顺序的测试替身证明：不允许格式的字节在调用Sharp之前已经停止；不能仅凭最终“报错了”判断安全。
- 使用无害合成格式样本，不在生产运行漏洞利用文件。
- 新投稿、账号草稿、图片替换和现有发布流程全量回归；失败时没有虚假成功，不破坏旧草稿、收据或图片。
- 目标图片库告警消除；其余依赖告警逐项记录用途、可达性和处理结论，不把“数量变少”当全部解决。
- 正式构建与原有隔离检查通过。原始发布副本、inbox图片及真实业务数据不被批量重编码或修改；如衍生图因编码器差异变化，单独列出，不能冒充源图片未变。

参考：[Sharp libheif公告](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c)、[Sharp librsvg公告](https://github.com/lovell/sharp/security/advisories/GHSA-wq5f-xc86-pv6w)、[Astro AVIF公告](https://github.com/withastro/astro/security/advisories/GHSA-26w7-cxv4-gfx2)。公告下限不是“未来所有漏洞均安全”的保证，实施时仍重新审计。

## 四、第2项：详情页文字数据安全输出

### 准备怎么改

1. 为嵌入HTML脚本数据块的JSON建立一个小型共用安全输出函数，统一处理会截断页面的`<`等字符；不使用“删除特殊文字”的方式解决。
2. 修复`site/src/pages/archive/[id].astro`中的`record-view-data`，并核对搜索索引、结构化数据及其他同类输出点，统一安全规则，避免下一次遗漏。
3. 普通页面文字继续使用框架默认转义，动态插入文字继续使用`textContent`；HTML属性数据由框架负责安全编码，不能混用多种上下文的转义方式。
4. 不修改题名、原文、图片说明或译文数据本身，访客看到的正常文字及复制内容保持一致。

### 怎么证明修好

- 合成题名/图片说明包含大小写脚本结束标签、尖括号、引号、换行、中文与其他语言字符时，只出现预期的数据块，不生成额外网页元素或可执行脚本。
- 对生成结果重新解析JSON，内容与输入逐字一致，防止重复转义把页面显示成反斜杠字符。
- 浏览足迹、引用复制、搜索、六语言题名及轮播均正常，现有正式构建和全部测试通过。
- 真实档案及公开文案的文件校验值不变；验证只使用隔离合成资料。

参考：[Astro关于set:html的安全说明](https://docs.astro.build/en/reference/directives-reference/#sethtml)。

## 五、第3项：完整缓存规则

缓存的目标是：页面更新可及时确认，版本化程序可复用，私密内容不进入共享缓存。不是把所有页面都设为长期缓存。

### 规则设计

| 内容 | 默认方案 | 原因 |
| --- | --- | --- |
| 六语言公开HTML，包括相册、详情、说明页 | `public, max-age=0, must-revalidate`，保留ETag/Last-Modified | 可以保存副本，但再次使用前向服务器核对是否更新。 |
| 带内容版本号的`/_astro/`程序、样式、字体 | `public, max-age=31536000, immutable` | 文件内容变化时网址也变，旧文件可长期复用。 |
| 发布图片、响应式图片 | 初始采用`public, max-age=0, must-revalidate` | 这些网址不是内容哈希网址，图片可能替换或随档案撤下，先保证更新与隐私。 |
| `records.json`、robots、站点地图 | 重新核验策略，不长期固定旧内容 | 防止题名、译文可用状态和撤下结果停留在旧版本。 |
| 登录/用户中心、管理域名、全部业务API | `no-store`，不进入共享缓存 | 防止账号或私密结果复用给其他访问者。 |
| 缺页与拒绝访问响应 | 初始不持久缓存，保留真实404/401/403 | 避免后来恢复的页面仍被旧错误响应遮住。 |

### 准备怎么改、怎么验收

- 更新既有Caddy缓存模板和安装/回退检查，覆盖简中、英、泰、日、韩、繁体与相册路径，明确静态匹配不能覆盖API和管理域名。不新增CDN服务。
- 本地验证规则匹配与优先顺序；上线前备份原配置，执行Caddy配置校验。获授权后只重载既有服务，失败恢复原配置。
- 分别验证首次访问、ETag条件请求、页面更新后再次访问、CSS/JS版本变化、图片替换与撤下、账户和错误响应。
- 采用合成版本演练更新和撤下，不拿真实档案做实验；不能因为缓存测试而恢复已经撤下的内容。
- 强调边界：重新核验规则可减少再次访问时使用旧内容，不能收回访客已经下载的文件或已打开页面。已经存在的旧缓存需核验更新路径，不能承诺配置一开所有旧副本立即消失。
- 如果现有代理还有其他缓存层，核验同一路径的实际响应与缓存状态，再决定是否刷新受影响路径；不擅自更改其他域名或全站代理策略。

参考：[MDN Cache-Control说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Cache-Control)。

## 六、第4项：加载性能优化

### 第一步：语言字典按需加载

- 分离“构建时生成文案”的模块和“浏览器运行时文案”的模块，避免`client.ts`经`ui.ts`把全部语言字典带入访客浏览器。
- 浏览器只初始化当前页面语言需要的固定文案；保持现有参数插入值、访客输入及原始转录不被再次翻译。
- 保持`clientText`等既有调用的正确性：依赖字典的功能必须在字典准备好后启动，不允许出现先用错误语言绑定按钮、稍后只改表面文字的情况。加载失败显示可读提示和重试/普通链接，不让表单假装可提交。
- 首页独立轮播继续不依赖整套字典，正文和普通链接仍优先由静态页面提供。

### 第二步：目录去重复与减少首次渲染负担

- 先分开测量卡片HTML、检索索引和重复字段的占比，只去重复和缩减表示方式，不删检索字段、不丢跨语言检索能力。
- 优先只保留首屏需要的完整卡片DOM，其他卡片在当前分页需要时生成；所有插入内容保持安全输出。非JavaScript情况下仍须有可用目录与正常档案链接，不能变成空白页。
- 保留现有每页数量、相册收拢/逐件模式、逐件总数、排序、筛选、URL参数与返回位置恢复，不更改首页轮播选择规则。
- 如果小范围去重复仍不足，需要改成新的静态分页网址或调整浏览方式，先列出必要性和影响，另行确认；不直接引入后端搜索服务。

### 量化验收

以同一份已公开资料、相同页面和浏览器条件对比，记录未压缩体积、gzip传输体积、初始请求依赖树、DOM数量及搜索响应。

- 设计目标：中文首页初始JS的gzip总量较基线减少至少50%；目录HTML的gzip体积减少至少25%。这不是已实现结果，也不换算成未经测量的“快几秒”。
- 其他语言也须减少不必要字典，不允许中文改善却让另一个语言首次请求显著增加。
- 有/无结果、组合筛选、跨语言检索、分页、语言切换、足迹和相册计数结果保持一致；320/390/1280宽度没有新增整页溢出。
- 如果未达目标，说明实际瓶颈和取舍，不删除内容或关闭功能来凑减小比例。所有功能回归是硬条件，性能数字不能替代正确性验收。

## 七、第5项：外语内容复核

此项主要是内容更新与审核，不是把保护门禁关掉。122是体检时的页面数量，不是122份独立译文，也不要求不顾事实强行清零。

### 准备怎么做

1. 从现有翻译状态和来源指纹生成新的私密待复核清单，按“永久编号＋语言＋失效字段”归并，区分中文来源变化、缺译、图片说明变化与相册派生状态，避免对同一分件重复处理。
2. 先复核首页精选和主要相册相关内容，再分批处理其他记录；原英文快照较多，可优先英语，但不把同一改动误覆盖到其他语言目录。
3. 只为失效/缺失字段准备修订草稿，已核验且来源未变的译文保持不动。先处理分件，再依据实际状态重算相册页，不手工把相册页标成全部通过。
4. 保留不确定性、推测提示、原始转录、年代、数量、地点及权利事实。遇到无法核实的真实事实，交给所有人判断；不利用照片推断人物身份。
5. 沿用现有预览、逐字段审核和发布入口。草稿不直接覆盖公开译文，未经审核的页面保持原文回退与`noindex`；首页、列表与详情的状态提示应一致，不把混合语言伪装成已译完。
6. 审核时再次核对来源版本；中文或图片在审核期间变化，则对应字段重新进入待复核，不沿用过期确认。人工批准与发布范围以每批清单为准，不执行全库“重新认可”。

### 怎么证明完成

- 逐批提供“已完成、仍待复核、需用户判断”的清单；不能只报告待复核页数下降。
- 编号、分类代码、图片、中文资料、原文转录、隐私/发布状态不变；不同语言草稿、正式版本与历史互不覆盖。
- 已审核且来源有效的页面正常生成对应题名/说明、语言替代关系与站点地图；未通过的页面继续排除收录。
- 六语言公开编号集合一致，无因翻译维护而新增/丢失档案。仅内容页的可收录范围随审核状态正常变化。
- 真实译文保存/审核发布前保留可恢复历史；生产操作获得对应授权，不用本机译文目录整体覆盖服务器。

## 八、每批共同的验收与回退

1. 开始前记录当前代码、受影响文件、服务/运行库版本和本次资料基线，保护现有工作区改动。
2. 使用隔离合成资料先跑针对性测试，再跑管理与点赞全量测试、现有正式`build`和公开隔离检查。生产以服务器自身资料构建，不复制本机生成数据。
3. 交付各批修改清单、测试证据、仍未验项目和回退方法。按用户后续要求，五点全部完成并核对统一线上操作授权后，才推送会触发部署的分支或修改服务器配置。
4. 上线后核验六语言、关键交互、账户私密响应、图片及资源版本；能做实际浏览器验收就保存证据，受工具限制的项目明确标待验，不能用静态检查冒充真机验证。
5. 代码/配置失败恢复对应程序或配置，不用回退程序顺带覆盖后来新增的档案、账号或译文。译文仅按其自身历史恢复。
6. 安全批次若只能退回带已知风险的旧图片库，不能把“恢复原样”当安全完成。是否临时暂停新上传须事先取得用户明确授权，并保持公开浏览可用；不擅自关闭注册、清空稿件或重置账号。
7. 每批更新开发日志，通过验收后停止，等待下一阶段指令。

本次方案文件不构成任何一项“已修复”或“已上线”的证明；备份恢复、安卓真机，以及本次未列入的其他整改项仍保留原待办状态。
