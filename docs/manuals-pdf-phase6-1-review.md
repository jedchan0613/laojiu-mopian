## 三 清晰度与异常文件

### 字体和页面表现

在2400像素长边、JPEG质量90的图上，查看了合成样例的12／10／8／6pt中文、英文与数字、0.15pt起的细线、图表和纸面页序标记。内嵌中文和该样例的未嵌入中文在所检图像上可辨认；手机整页缩放适合浏览，小字需要切到原尺寸查看。

工具同时输出了Symbol、ArialUnicode、STSong-Light字体查找或替代诊断。可辨认的截图不能证明全部字体或其他说明书都可正确转换，因此字体覆盖尚不作为普遍通过。后续完整工具复验需区分经人工核对的替代提示与实际缺字、乱码、空白，诊断未核对前不能把进程退出码0当作清晰度验收成功。

默认建议保持2400像素。本次3300像素对照生成312,903字节，默认页生成196,867字节；提高尺寸会增加体积，并不能解决字体缺失。A4直接使用4096像素长边会超过800万像素，因此计算约定同时限制长边及总像素，不能仅检查4096这个数字。

旋转、横版、裁切与批注页均生成了私密检查图。输出尊重CropBox、比例与旋转，没有要求隐藏批注；可见手写字、签名和号码仍必须经过原有人工隐私检查。扫描PDF按图片生成，不能因原图文字已经模糊而宣称转换后更清楚。

### 异常文件的结果

- 有打开密码的文件由工具拒绝；所有者加密及限制复制打印的文件明确识别为加密。不传递密码，不使用绕过限制的参数。
- 脚本文件显示JavaScript标记，表单文件显示AcroForm，均按首版不支持处理。
- 201页、零页、超20 MiB、伪PDF、损坏文件和异常大页面分别由文件初筛、工具失败或边界规则阻止；不截取部分内容假装成功。
- 包含合成附件的文件用来证明当前检查缺口；未将附件内容提取或执行。制作样例使用的pypdf仅属于测试环境，不替代生产附件检查，也没有作为项目新增依赖。
- 多页的尺寸检查必须覆盖每一页；只检查第一页会得到 `page_geometry_incomplete`，不能据此批准整册。

所有转换都明确限定为自己生成、内容已知的静态样例。即使缺少完整检查工具，也没有把任意来稿送入实验转换器。

## 四 Windows隔离实验的实现与边界

实验使用Windows自带API和本机已有编译器，不安装框架或常驻服务：

1. 新建临时AppContainer配置，显式不授予网络能力。
2. 仅给合成输入目录只读权限、合成输出目录写入权限，工具目录只读执行。
3. 用受控参数启动挂起进程，将其加入设置512 MiB限制及关闭时终止的Job，再恢复执行。启动前不能让转换器先跑一段时间。
4. 检查实际令牌，运行合成文件、网络与内存探针，测试超时和取消结束整个Job。
5. 检查活动进程为0，删除临时配置，撤销新测试目录的临时ACL并还原完整性标签。

最初不创建临时配置的试验无法启动AppContainer；随后用官方的临时配置流程验证。另一个问题是过度精简标准Windows环境变量会导致启动错误，改为仅传必要的标准系统路径变量后成功。没有继承邮件密钥、账号令牌等应用环境变量。

实验代码在Git忽略的outputs中，是验证材料，不是已经接入业务的安全沙箱。正式处理器需要把每个任务的身份、权限、有限标准输出捕获、版号复核和清理封装成可维护实现；不能直接把整份实验脚本放到公开服务上。原始实验的200页性能对照在同一合成任务中执行，最终另用独立输入／输出／其他任务目录证明权限边界。

没有读取真实账号密钥、真实投稿或项目外主库来试探权限。被拒绝的是普通私密目录权限下的合成标记，实际部署仍须验证真实数据目录的权限配置及必要的字体／系统文件访问。

## 五 后续适配器约定

新增 `local-admin/manual-pdf-tools.mjs`，仅提供盘点与纯检查函数，未被服务端、账号接口或公开构建调用：

| 函数 | 输入与输出约定 |
| --- | --- |
| inventoryManualPdfTools | 配置的绝对工具目录及批准的摘要；只读取文件，返回三个必要命令是否齐全、大小与摘要，不执行程序、不从PATH猜测 |
| parseManualPdfInfo | 有限工具输出；返回页数、加密、脚本、表单、字节数、版本和已检查的页面尺寸，不带作者、标题等私密属性 |
| parseManualPdfAttachmentCount | 明确的附件列表输出；只有已完成的0附件报告才返回0，缺失、重复或异常输出均失败 |
| manualPdfPageProfile | 源页尺寸与目标长边；同时保证长边不超过4096、总像素不超过800万，异常几何停止 |
| manualPdfInspectionIssues | 文件和可信处理端的检查结果；工具、隔离、附件缺失、来源变化、异常页数、未完整检查页面、字体诊断等返回具体问题 |
| manualPdfReadiness | 汇总可信维护配置中的工具、版本、许可、字体、隔离、完整依赖包及实际业务接入证据；新增bundlePinned与integrationVerified要求，单个exe摘要或本轮实验不能代替业务接入检查；它不是可由浏览器声明的安全令牌 |

这些函数是下一阶段的边界约定，不构成完整PDF解析或沙箱，也不表示允许接收不可信文件。实际处理器应先验证输入摘要，逐页检查尺寸、限制每页与全册时间及容量，使用有限管道捕获诊断，并在提交整册结果前重核源文件、版号与停止申请。

当前PDF业务接入就绪结论仍为false，上传、原PDF公开和自动处理没有开放。本轮工具技术验收通过与业务接入是两个不同结果；现有图片投稿及5.4审核流程没有改动。
