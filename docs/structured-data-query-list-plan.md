# 档案结构化数据查询列表方案（第一阶段已实施）

实施状态：2026-09-01 已完成第一阶段。本地档案管理已增加“资料查询”，通过 `/api/query-records` 只读白名单接口提供正常／已撤销切换、搜索、常用筛选、50 条分页、无图片结果列表、结构化详情和“在档案管理中打开”。查询响应不包含图片网址、主档路径、完整证件号码、完整地址、签名或指纹；CSV 导出和查询页直接编辑仍未实施。

## 1. 目标与边界

本方案面向本地档案管理入口，用于快速查找、核对和比较档案的结构化信息。查询时不加载、解码或显示任何图片，只读取档案 JSON 和响应式图片清单 JSON 中已经存在的结构信息。

明确边界：

- 不显示缩略图，不生成图片预览，不向图片地址发起请求。
- 不扫描 TIFF、RAW、原始扫描件或档案主库；不读取图片像素、EXIF、人脸或图片文字。
- 图片相关内容只显示“有几张、说明是否完整、发布路径是否登记、响应式副本是否齐全、校验值是否存在”等结构状态。
- 查询页只属于 `local-admin/`，只监听 `127.0.0.1`，不得进入公开网站构建目录。
- 第一版只读，不在查询结果中直接编辑、撤销、发布或删除档案。
- 第一阶段已经创建本地页面与只读接口；仍不进入公开网站构建目录。

## 2. 建议入口与页面结构

建议以后在本地档案管理左侧增加独立的“资料查询”，与“档案管理”“维护概览”平级。默认查询正常档案，已撤销档案通过状态子菜单单独切换。

```text
资料查询
├─ 状态切换：正常档案｜已撤销
├─ 快速搜索：编号、题名、收藏品编码、人物、机构、地点、来源
├─ 常用筛选：类型、年代、地点、研究状态、证据等级、权利、图片结构
├─ 结果摘要：命中数量、当前条件、清除条件
├─ 数据列表：只显示文字和状态，不显示图片
└─ 右侧详情：当前记录的完整结构化摘要，只读
```

桌面端使用表格，手机端自动改为紧凑资料卡。筛选栏保持在列表上方，滚动时固定表头；每页建议 50 条，避免一次渲染过多字段。

## 3. 默认列表字段

默认列只保留能帮助识别、筛选和判断资料完整性的内容：

| 列 | 显示内容 | 数据来源 |
| --- | --- | --- |
| 状态 | 正常、暂停、已撤销；草稿与已发布另用小标记 | `record_status`、草稿状态、`use_status` |
| 永久编号 | `LJM-YYYYMMDD-TYP-NNN` | `item_id` |
| 题名 | 当前档案题名 | `title` |
| 类型 | 中文标签与正式对象代码 | `object_type`、代码字典 |
| 年代 | 显示年代；可辅助显示起止日期 | `date_display`、`date_start`、`date_end` |
| 地点 | 省、市、区和具体地点合并后的短摘要 | `province`、`city`、`district`、`specific_place` |
| 研究判断 | 研究状态、证据等级 | `research_status`、`evidence_level` |
| 公开边界 | 隐私、权利、利用状态 | `privacy_level`、`rights_status`、`use_status` |
| 图片结构 | 例如“2 张 · 说明 2/2 · 发布副本完整” | 见第 5 节 |
| 最近更新 | 最近维护日期 | `updated_date` |

批次编号、来源、人物、机构、收藏品编码和物理位置默认不占表格宽度，但可以在“选择列”中开启，也会进入右侧详情摘要。

## 4. 查询与筛选规则

### 4.1 快速搜索

一个搜索框同时匹配：

- 永久编号、收藏品编码、批次编号和题名；
- 人物、机构、来源人／机构；
- 公开地点及省、市、区、具体地点；
- 主题和事件场景的中文标签；
- 图片说明文字，但不读取图片本身。

多个关键词按“同时满足”处理。例如输入“珠海 1989”，只返回同时包含珠海线索和 1989 年代线索的档案。正式代码与中文标签都能搜索，但列表优先显示中文标签。

### 4.2 常用筛选

- 档案状态：正常、暂停、已撤销；默认正常。
- 藏品分类与精确类型：先按七类访客分类筛选，需要时再选 `PHO`、`PST` 等正式类型。
- 年代与地点：年代区间、省、市、区。
- 研究质量：研究状态、证据等级、是否待复核。
- 公开边界：隐私等级、权利状态、利用状态、是否已有公开页面。
- 图片结构：无发布副本、单图、多图、说明不完整、路径不完整、响应式副本不完整、缺少校验值。
- 数据完整性：缺少必填项、收藏品编码待生成、专属 schema 不匹配。

所有筛选条件都显示为可单独移除的条件标签，并提供“清除全部”。切换正常／已撤销状态时保留其他筛选，但不混合显示两种状态。

## 5. 图片结构信息的定义

查询列表不查询图片内容，只从现有 JSON 生成以下只读字段：

| 派生字段 | 含义 |
| --- | --- |
| `publication_image_count` | `publication_file_path` 中登记的发布副本数量 |
| `access_image_count` | `access_file_path` 中登记的访问副本数量，只显示数量，不显示完整本地路径 |
| `description_complete_count` | `image_descriptions` 中非空说明的数量，显示为“已填写数／图片数” |
| `image_order_status` | 发布路径与图片说明的顺序和数量是否一一对应 |
| `responsive_variant_status` | 响应式图片清单中 320、640、1280、1920 四档是否齐全，仅查询清单 JSON |
| `checksum_status` | 是否登记 SHA-256 校验值；列表不展示完整校验值 |
| `publication_structure_status` | 综合显示“完整、需补说明、路径不一致、缺少网页尺寸副本” |

右侧详情可以按顺序列出“第 1 张／第 2 张、文件名、图片说明、响应式副本状态”，但不得使用 `<img>`、CSS 背景图或其他方式请求文件内容。完整绝对路径和主档路径不进入前端响应。

## 6. 右侧只读详情

点击一行后，在右侧展开结构化详情，不离开查询结果：

1. 身份：永久编号、收藏品编码、批次、题名、类型。
2. 时间与地点：显示年代、起止日期、省市区和具体地点。
3. 人物与内容：人物、机构、事件场景、主题。
4. 来源与保存：获得方式、来源、保存状态和物理位置。
5. 研究与权利：研究状态、证据等级、隐私、权利和利用状态。
6. 对象专属摘要：只展示当前对象 schema 下有值的维度，不平铺其他类型的字段。
7. 图片结构：数量、说明完整度、路径登记和网页尺寸副本状态。

详情底部只提供两个低风险入口：“在档案管理中打开”和“复制永久编号”。第一版不在查询抽屉中提供保存、发布、撤销或图片操作。

## 7. 建议的数据投影

未来实现时，由本地服务把完整档案转换成白名单查询投影，而不是把全部 JSON 原样传给列表：

```ts
interface RecordQueryRow {
  item_id: string;
  collection_code?: string;
  title: string;
  category: string;
  object_type: string;
  date_display: string;
  place_summary: string;
  people_summary: string[];
  organization_summary: string[];
  theme_labels: string[];
  record_status: string;
  research_status: string;
  evidence_level: string;
  privacy_level: string;
  rights_status?: string;
  use_status: string;
  publication_image_count: number;
  description_complete_count: number;
  publication_structure_status: 'complete' | 'warning' | 'missing';
  updated_date?: string;
}
```

多值字段在投影中继续使用数组，不提前拼成分号字符串。代码值和中文标签分别保留，显示时使用中文，筛选与核验仍使用正式代码。

## 8. 后续实现建议

如果确认实施，建议一次只完成以下第一阶段：

1. 在本地服务增加只读投影函数和查询接口，接口仅返回白名单字段。
2. 增加“资料查询”工作区、正常／已撤销子菜单、搜索、常用筛选和分页列表。
3. 增加只读详情抽屉和“在档案管理中打开”。
4. 增加“不产生图片请求”的自动回归检查，并确认查询页不进入 `site/dist/`。

当前档案量不需要数据库。继续读取 `archive-data/*.json` 并在本地内存中建立临时索引，方案更简单、稳定且容易维护；只有档案数量达到数千件、实际查询速度出现问题后，再单独评估 SQLite。

## 9. 验收标准

- 打开查询列表时，浏览器网络记录中没有 `/archive/`、`/archive-responsive/` 或本地图片接口请求。
- 默认只显示正常档案，已撤销档案必须主动切换后查看。
- 搜索和筛选只读，不修改草稿、正式记录、历史版本或图片回收区。
- 查询结果中的类型、状态和代码标签与现有代码字典一致。
- 图片数量、说明数量和路径数量不一致时，列表能明确标为“需检查”。
- 证件只显示已遮盖字段；完整号码、完整地址、签名、指纹、主档路径和完整本地绝对路径不得出现在响应中。
- 查询页面、脚本和接口不进入公开构建目录，公开网站构建结果保持不变。
