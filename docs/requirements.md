# 老旧默片 V1.0 网站需求

## 1. 项目定位

“老旧默片”是一个个人数字档案网站，用于整理和展示经过筛选、压缩及必要脱敏的旧资料和旧物发布副本。

V1.0 的目标是完成一个简单、清晰、适合手机和电脑浏览的档案展示网站。第一版以浏览和查找档案为主；按用户后续明确要求，只增加无需账号的档案点赞，不扩展评论、社交关系、交易或自动识别功能。

## 2. V1.0 功能范围

1. **首页**：作为网站入口，介绍“老旧默片”并提供进入档案内容的方式。
2. **档案列表页**：集中展示已经发布的档案，方便用户逐项浏览。
3. **单件档案详情页**：展示一件档案的发布副本及其可公开的说明信息。
4. **分类浏览**：按照档案类型查看内容。
5. **年代筛选**：按照档案所属年代筛选内容。
6. **地点筛选**：按照档案相关地点筛选内容。
7. **标签筛选**：按照档案标签筛选内容。
8. **关键词搜索**：通过关键词查找相关档案。
9. **手机浏览**：网站在常见手机屏幕上能够正常阅读和操作。
10. **电脑浏览**：网站在常见电脑屏幕上能够正常阅读和操作。
11. **档案点赞**：首页、档案列表和单件详情页均显示同一份档案点赞数；同一访问地址对同一件档案只计一次，不保存原始 IP。
12. **信件阅读**：正式对象类型为 `LET` 的档案默认提供适合长文阅读的公开转录，并可在文字阅读、原件对照和只看原件之间切换；电子文字不替代原件依据。

## 3. 档案类型

数据模型升级后，网站采用以下正式对象类型。旧页面中文分类仍可合并展示这些代码，但数据内部保留正式代码。

| 类型名称 | 中文说明 |
| --- | --- |
| `PHO` / `NEG` / `SLD` / `ALB` | 照片正片、底片、反转片和相册 |
| `PST` / `PCD` | 明信片和照片明信片 |
| `DIA` / `NTB` | 日记和笔记本 |
| `IDC` | 证件 |
| `LET` | 信件 |
| `RPR` | 复制件 |
| `OTH` | 其他 |
| `card` | 旧卡片 / 信用卡；保留为待扩展类型，尚无正式对象代码和专属 schema |

公开网站不直接把上述精确类型全部暴露为主分类。首页和档案筛选统一使用七个访客分类：

| 访客分类 | 包含的正式或待扩展类型 |
| --- | --- |
| 老照片 | `PHO`、`NEG`、`SLD`、`ALB` |
| 明信片 | `PST`、`PCD` |
| 信件 | `LET` |
| 老证件 | `IDC` |
| 旧卡片 | `card` |
| 笔记与笔记本 | `DIA`、`NTB` |
| 其他旧物 | `RPR`、`OTH` |

访客分类只用于导航和筛选。档案详情仍显示精确对象类型；本地管理和正式数据继续使用 `object_type`，不得把访客分类写成新的元数据代码。

## 4. 内容与隐私边界

- 网站只使用发布副本，不直接读取或展示原始档案主文件。
- 发布副本必须经过筛选、压缩和必要的脱敏处理。
- 原始高清扫描件和敏感资料继续保存在独立的本地档案系统中。
- 无法确认是否适合公开的资料，默认不进入网站公开目录。

## 5. 视觉方向

网站整体视觉应体现以下感受：

- 安静。
- 克制。
- 怀旧。
- 私人档案馆。
- 老书与旧纸张。
- 摄影档案感。

视觉设计应以档案内容为主，不使用喧闹、过度装饰或影响阅读的效果。

## 6. V1.0 暂时不做

- 注册登录。
- 评论。
- 支付。
- 电商。
- 用户账号与自行公开发布（本次已授权的免注册投稿见第 8 节）。
- APP。
- AI 人脸识别。
- 自动 OCR（自动识别图片中的文字）。
- 复杂 CMS 后台（复杂的内容管理后台）。
- 多人权限系统。

以上功能均不属于 V1.0 范围，未经用户明确提出，不提前设计或开发。

## 7. 未来规划：开放用户分享

未来版本计划开放注册，让用户分享和上传以下老旧默片资料：

- 用户自己的资料。
- 用户家人的资料。
- 用户本人收藏或遇到的老旧默片资料。

这是一项长期方向，不属于当前版本的开发范围。未来正式启动前，需要另行明确账号安全、上传授权、家人及其他真实人物的隐私同意、版权与使用许可、敏感信息处理、内容审核、发布确认和撤回机制。用户上传的内容不得未经审核直接公开，也不得降低项目现有的隐私保护和发布副本规则。

## 8. 已授权：免注册投稿与私密审核

2026 年 9 月 5 日，用户明确要求设计并开发免注册投稿。当前范围为：公开投稿页、联系方式与资料介绍、筛选副本上传、授权确认、投稿编号及私密查询回执、私密审核列表、人工确认后转为未公开草稿，以及停止处理申请。

为此增加轻量的投稿接收程序，沿用现有 Node.js、文件存储与图片处理能力，不安装新依赖、不建数据库。公开接收与管理员审核保持分离；投稿内容不得直接进入公开目录或绕过既有档案入站与正式构建检查。注册系统、自行发布和其他未经授权功能仍不在本次范围内。

设计、使用和上线衔接详见 `docs/submission-guide.md`。本次完成开发与本地验收，服务器上线另行处理。
