# 相册录入与整册浏览方案（复核修订版）

修订日期：2026-10-15
状态：本地修复与验收完成，尚未提交、推送或部署生产服务器。
本版取代 2026-10-14 初稿中关于字段位置、编号格式、排序和“批量补录”的说明。检查结果见 [相册功能复核记录](album-intake-and-browse-review.md)。

## 1. 一册一条总档案，一张照片一条档案

一本相册建立一条相册总档案（ALB）；其中每张需要独立描述、检索的照片建立照片档案（PHO）。照片正面、背面、局部细节是同一张照片的多个附件，不重复建立照片档案。相册封面、封底、整页记录可作为 ALB 的附件。

| 字段 | 用途 | 填写原则 |
| --- | --- | --- |
| 永久编号 item_id | 标识一件藏品 | 保存时按正式规则生成；分类或研究结论变化也不改号 |
| 相册编号 album_id | 识别属于同一本相册 | ALB 与各张 PHO 共用同一个值；新册可直接使用总档案的永久编号 |
| 原始位置 original_position | 记录照片在册内的位置 | 如“第3页右上”“第三页第2张”；不清楚时留空，不按照片年代重排 |
| 批次编号 batch_id | 标识同批获得的资料 | 保留原有入藏含义；同批可以包含多本相册，不代替相册编号 |

年代、拍摄地点、人物与内容分别记录在每张照片自己的字段中。相册整体年代只是总册描述，不能自动成为每张照片的年代。总册与照片仍沿用现有 core / metadata / public_view 和 photo schema，不新增元数据代码。

## 2. 维护操作

1. 在本地管理入口新建档案，首页分类选择“老照片”，精确类型选择“相册（ALB）”。
2. 填入题名、批次等信息并保存草稿，系统分配永久编号。
3. 在“本册关联信息”点击“使用本册永久编号”，再次保存。已有相册编号的继续沿用；此辅助按钮只补空值，不能替换已有关系。
4. 点击“新增同册照片”。新档案类型为 PHO，沿用相册编号、入藏日期、批次、获得方式和来源。题名、年代、拍摄地点、原始位置、图片、专属字段和隐私确认均需分别填写。
5. 为照片添加经筛选的发布副本，填写该张照片的信息、原始位置并保存草稿；可继续点击“新增同册照片”。
6. 用“查看同册档案”核对整册。清单清除其他筛选条件，先显示总档案，再按原始位置显示照片；总档案标为“整册资料”。
7. 按原有流程逐件补齐必填字段，核对图片、隐私和权利，再正式发布。保存草稿和选择相册都不等于公开发布。

PHO 的“相册归属（可选）”单独放在常用档案信息后；散张照片可跳过。已有相册选择器显示题名、编号和维护库中的照片数量。ALB 显示“本册关联信息”，空的原始位置字段不向总册要求填写。其他类型原有的关联字段值继续保留和维护。

“同册维护清单”是筛选、核对和连续录入入口，**不是一次覆盖多张照片字段的批量修改工具**。未保存修改时禁止直接新建同册照片，先保存当前记录；撤销记录保持只读。

## 3. 提醒与发布检查

- 缺少总档案：允许先录照片，提示后补 ALB，不阻断草稿或单张发布。
- 位置为空、无法解析：提示完善，原始文字保留；不编造页码。
- 唯一页内位置重复：中文与阿拉伯数字等价判断，例如“第三页右上”和“第3页右上”会提示核对。同一页有多张照片很正常，单独“第3页”、整页、封面等不被误判为唯一位置重复。
- 多个有效 ALB 使用同一相册编号：可先保存草稿修正，但正式发布阻断。撤销总档案不占用关系；已有正式关系不能被另一条未发布草稿的改名隐藏。
- 修改已有总册的相册编号：明确提醒其他照片不会自动跟随，需逐件核对。
- 相册编号和原始位置必须是合理长度的文字，拒绝控制字符及路径形式输入。旧中文、空格和下划线编号可以沿用。
- 原有字段、对象类型与 schema、图片路径和人工隐私确认检查保持有效。新建照片仍为待整理、限制公开、未使用状态（SUS / Y / U0）。

## 4. 公开展示

从 ALB 或任一已公开 PHO 的详情页进入整册页面。页面延续现有网站的纸色、字体、页宽和导航，照片网格具有独立样式，桌面三列、较窄屏幕两列、很窄屏幕一列。封面和照片均保持完整比例。

- 相册标题、简介、封面优先取已公开的 ALB。
- 数量明确标为“已公开 N 张照片”，只数 PHO，不把总册、信件或附件数量算作照片。
- 仅包含正常、已发布、可公开的资料（ACT / U3 / G）；草稿、撤销、暂停和隐私未通过内容不进入相册。
- 年代范围汇总公开照片自己的起止年份、显示年代及年代区间，同时标出年代待考照片数量；不继承总册年代，也不改写任何单件原始字段。
- 照片顺序为封面/扉页、数字页码、同页位置或张序、封底、无法确定页序、未填位置。同页常用位置顺序为左上、右上、左下、右下；位置文字保持原样。
- 支持“第三页右上”“第10页第2张”“3-2”“page 3”等常见写法；编号中的数字或“1993年合影”不当作页码。
- 照片详情页提供相册入口和同册上一张/下一张；页尾导航与页首采用同一套相册顺序。中英文顺序一致。
- 没有公开总档案时说明总档案尚未公开，仍可浏览已公开照片；只有总册、没有公开照片时显示明确空状态。
- 中文与英文均有对应页面。英文译文尚未审核的内容保留中文并提示，不把该英文页面作为已完成译文提交搜索引擎。

公开地址为 /albums/a-稳定摘要/ 及 /en/albums/a-稳定摘要/。地址从相册编号生成稳定摘要，不直接把维护编号作为文件路径，因此旧中文编号不会丢失页面，也不会形成私密目录名。维护时不需要输入或记忆这个网址。

本阶段从单件详情进入相册；首页七类和档案总目录继续使用原有结构，未另加公开相册总目录。

## 5. 实现与验证

页序解析只有一份：shared/album-position.mjs；网站构建和管理表单均调用它。管理服务只提供这一个模块的受控地址，不公开整个 shared 目录，不新增依赖或云服务。

验证使用独立目录 outputs/album-review-20261014/fixture/，不临时修改真实档案制造样例。样例覆盖总册、混合页序、重复位置、未知年代、非照片关联、隐私未通过、已撤销、没有总册和空册。

完成的验证包括：真实浏览器录入草稿与同册选择、桌面/手机及中英文页面、现有完整测试套件、真实数据正式 build、带相册样例正式 build，以及相册入口、数量、双语顺序和私密隔离构建检查。详见复核记录。
