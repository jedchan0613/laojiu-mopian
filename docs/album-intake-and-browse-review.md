# 相册功能复核与修复记录

日期：2026-10-15
结论：原实现存在页面样式失效、计数与排序不准、录入流程遗漏及验证覆盖不足，已完成本地修复。修订方案见 [相册录入与整册浏览方案](album-intake-and-browse-plan.md)。

## 发现与修复

| 问题 | 实际影响 | 修复结果 |
| --- | --- | --- |
| 相册页依赖其他页面的局部样式 | 网格未生效，大图横向溢出，手机难以浏览 | 相册页使用完整独立样式，桌面三列、手机两列、很窄屏幕一列；图片完整显示 |
| 同册数量把 ALB 或其他物件算进去 | “照片数量”与实际网格不一致 | 公开计数与网格只使用 ACT / G / U3 的 PHO；总册与信件不计入 |
| 年代只取部分显示年份 | 范围遗漏终点，未知年代被掩盖 | 汇总照片显示年代、时间起终点与年代区间，显示待考数量，不继承总册年代 |
| 页序仅提取数字、管理端复制算法 | 中文页码不识别，年份或编号可能误作页码，两端规则易漂移 | 一份共享解析器，支持中文、全角、页内张序、封面/封底；不改写原字段 |
| 直接使用相册编号生成路径并限制字母数字 | 旧中文、空格、下划线编号可能没有页面或产生断链 | 用稳定摘要生成网址，入口和页面使用同一套分组 |
| 没有总册或只有空总册时缺少完整处理 | 部分已公开照片没有整册入口，空册表现不清楚 | 无总册仍生成照片集合并说明；空册显示零张及空状态 |
| 相册字段藏在长表单中 | 用户不容易找到归属，ALB 也出现无须填写的位置 | 独立相册区域；照片可选已有相册，ALB 空位置不显示 |
| 保存后编号辅助按钮状态滞后 | 已分配编号仍不能点击，需要重新加载 | 随编辑与保存刷新按钮状态；只补空关联，不能覆盖已有编号 |
| 连续录入入口缺失或未保存时可触发 | 反复手填编号，可能丢失编辑或复制不合适的信息 | 新增同册照片只沿用入藏来源与相册关系，年代、拍摄地点、图片和许可独立填写 |
| “查看同册档案”按钮引用错误的搜索控件 | 点击发生运行错误，筛选没有生效 | 改为真实控件，清除其他条件，实测仅列本册总档案与照片 |
| 撤销状态和旧关联修改缺少保护 | 只读记录可能触发新建，旧照片归属容易断开 | 动作与按钮都检查只读/未保存状态；总册改编号提醒逐件核对 |
| 关联输入及重复总册缺少正式发布校验 | 异常输入可保存，一个编号可能对应多个总册 | 保存校验输入；正式发布阻断重复有效 ALB，保留草稿修正能力及人工隐私门禁 |
| 照片页首、页尾使用不同翻阅顺序 | 读完后可能跳到另一张或另一本相册 | 同册照片页首与页尾按同一套页序翻阅；中英文一致 |
| 构建检查没有覆盖待翻译相册页 | 无相册数据时构建通过，有样例时英文状态误报失败 | 补齐相册译文状态检查、真实链接检查、计数与中英文顺序检查 |
| 方案把筛选视图称作“批量补录” | 容易误以为已经提供多条字段批量修改 | 改为“同册维护清单”，写明逐张维护与连续新建的操作步骤 |

## 验证结果

- 完整现有测试套件：132 项，131 通过、0 失败、1 项既有 Windows 跳过。记录：outputs/album-review-20261014/tests-final.log。
- 真实本地数据正式构建：在 site/ 执行 npm run build，238 个页面、108 个档案详情、226 个站点地图地址；公开页面、字体、图片、联系挂件与管理端隔离检查通过。记录：outputs/album-review-20261014/main-build-final.log。
- 独立样例正式构建：262 个页面、117 个公开档案详情，包含三组相册的中英文页面；238 个站点地图地址。相册入口、照片计数、照片详情及中英文顺序检查通过。未公开译文页不加入站点地图。记录：outputs/album-review-20261014/fixture-build-final.log。
- 浏览器实测：新建 ALB → 保存分配编号 → 使用永久编号 → 保存 → 新建同册 PHO → 单独填位置并保存 → 查看同册清单，流程成功。
- 浏览器实测：改动未保存时“新增同册照片”禁用；中文与阿拉伯页码相同的位置会提示重复；选择相册后即时刷新提示。
- 桌面与手机检查：默认桌面和 390px 手机宽度下无横向溢出，公开网格为 5 张照片；照片顺序为封面背后、第1页、第2页、第2页、第十页。已知年代 1985—1995，1 张待考。
- 中英文实测：相册、总册和照片互相跳转正常；页首、页尾同册上一张/下一张地址相同；待翻译英文页有说明及 noindex。
- 边界实测：旧中文编号、无总册、空册、已撤销记录均按预期处理；公开页无运行错误。保存未命名草稿的自动保存错误属于原有题名必填门禁，填写题名后保存成功。

新增回归覆盖：album-data.test.mjs 验证分组、年代和页序；album-relation-tools.test.mjs 用隔离真实 HTTP 服务验证草稿、输入及发布门禁；album-editor-actions.test.mjs 执行实际编辑动作，验证筛选控件、逐张信息重置和只读保护。
