# 网站发布前隐私检查表

本表只检查准备进入“老旧默片”网站的发布副本，不用于保存或检查原始档案主文件。

逐项检查时，只记录“无”“有”或“不确定”，不要在检查表、文件名或开发日志中抄写实际的敏感号码和私密内容。

## 检查项目

1. [ ] 是否存在身份证号、护照号或其他身份识别号码？
2. [ ] 是否存在银行卡号、账户号码、完整卡号、安全码、密码或磁条/芯片可读数据？
3. [ ] 是否存在电话号码？
4. [ ] 是否存在门牌号、收件地址等精确私人住址？
5. [ ] 是否存在可以直接复制或辨认的清晰签名？
6. [ ] 是否存在病历、诊断、处方或其他医疗信息？
7. [ ] 是否涉及未成年人及其私人信息？
8. [ ] 是否包含明显私人日记、亲密关系或其他极私密内容？
9. [ ] 是否有可以识别的真实人物？
10. [ ] 是否存在未经确认的负面描述、指控或可能损害他人名誉的内容？
11. [ ] 是否已经把已知事实、合理推测和未知内容清楚区分开？
12. [ ] 当前图片是否确实是经过筛选的发布副本，而不是 TIFF、RAW 等主档或原始扫描件？
13. [ ] 是否需要先遮盖部分内容，再考虑公开？

## 处理规则

- 第 1 至 10 项或第 13 项回答“有”或“不确定”时，不得自动发布。Codex 必须停止入站，并提示用户进行人工判断。
- 第 11 项或第 12 项回答“否”或“不确定”时，必须停止入站，完成资料整理或重新制作发布副本后再检查。
- 涉及可以识别的真实人物时，Codex 不得通过人脸、背景、文字或其他线索猜测当事人身份，也不得把未经确认的身份写入藏品数据。
- 需要遮盖内容时，只能在另行制作的发布副本上处理，不得修改、覆盖或替换唯一主档。
- 旧卡片公开数据只能保存遮盖姓名和遮盖卡号；卡号最多保留末四位，不得读取、复制或验证磁条和芯片中的数据。
- 只有全部检查通过，并确认 `privacy_level = G`、`record_status = ACT` 后，资料才可以进入用户人工批准环节。
- `Y` 和 `R` 默认不得直接公开；`use_status = U3` 只能在用户明确批准正式发布后使用。批准前使用 `U1`（候选）或其他非发布状态。

## 检查结论

- [ ] 通过：可以进入网站待入站区。
- [ ] 暂停：需要用户人工判断或继续脱敏。
- [ ] 不适合发布：不得进入网站公开内容。
