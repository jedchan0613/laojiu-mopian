## 发现并修正的实验问题

- 初次低权限启动遇到输出目录和`/runtime`父目录无法穿越。只修正实验容器内的工作目录与必要父目录权限；实验根目录仍为0700，没有放宽业务目录权限。失败日志保留。
- 首次超时检查在`stop-sigterm`期间就检查PID，误报尚在结束的进程。改为等待`exited/dead/failed`终态，重新用含真实孙进程心跳的探针通过；原误报PID事后也确认不存在。
- 取消成功后systemd已回收临时单元，重复清理返回“not loaded”。只对本轮已知临时单元处理这一状态，重新取消验证通过，不把普通业务服务错误当作成功。
- 普通`ljmadmin`直接运行完整Bubblewrap隔离失败，实报`loopback: Failed RTM_NEWADDR: Operation not permitted`。没有关闭全局限制来重试；独立受控启动成功不能替代账号身份接入。
- 缺少字体的PDF在Linux上可能安静替换字体。必须保留`pdffonts`未嵌入字体标记并人工核对，不能仅凭退出码0或stderr为空就认定保真；原有整册核对与人工审核要求继续保留。
- 修正只读盘点脚本的公开指针路径为实际`/srv/laojiumopian/releases/live`，并检查它确实为链接；没有改动服务器指针。

Ubuntu对普通用户命名空间能力的限制及专用配置方案见[Ubuntu 24.04发行说明](https://discourse.ubuntu.com/t/ubuntu-24-04-lts-noble-numbat-release-notes/39890)。本次普通身份失败与该限制行为一致，但不会据此自行加载新规则或放宽现有权限。任务组控制参考[systemd 255资源控制](https://raw.githubusercontent.com/systemd/systemd/v255/man/systemd.resource-control.xml)。
