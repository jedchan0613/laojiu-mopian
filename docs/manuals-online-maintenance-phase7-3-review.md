# 说明书7.3：发布、撤下和恢复验收记录

日期：2026年11月13日。对应用户指令“执行7.3”，配套[接入设计](manuals-online-maintenance-phase7-1-design.md)、[45项验收清单](manuals-online-maintenance-phase7-acceptance.md)及[阶段计划](manuals-development-plan.md)。

7.3的本地开发和对应检查已完成：接入线上发布事务、撤下、恢复草稿、共享部署锁、停止与结果核对。当前服务器没有更新，不能据此称线上维护已经开放。真实Linux演练及整体验收由7.4完成，具体部署及生产开放由7.5另行授权。

## 一、已交付行为

1. 保存私密草稿后进行发布检查，确认品牌型号、隐私、来源、版本页序及本次公开影响五项内容。检查凭据绑定服务器确认的操作者、目录版本和附件摘要，不能沿用其他身份或已变化资料的旧检查。
2. 线上发布取得与Git部署相同的锁，记录前后版本及必要JSON，构建白名单公开输入。构建后及候选准备后再次检查目录、档案、附件和投稿停止状态，核实旧公开指针及程序位置后才切换。
3. 切换成功后核对真实公开版本，再保存正式目录状态及操作回执。构建、准备或切换失败可安全回退；状态落盘失败也纳入回退。遇到锁丢失、其他公开更新或无法证明的结果，保留材料并暂停相关写入，不自动续发。
4. 撤下要求原因与确认，沿用同一事务；移除说明书目录入口，保留原档案、图片、其他草稿及历史。恢复历史前保存已有草稿，恢复结果只成为草稿，重新检查和确认发布后才对外生效。
5. 页面显示维护进度，提供“查询结果”“请求停止”“核对异常结果”。关闭页面不等于停止；查询只读取原请求的结果，网络中断后不自动再次发布。构建中停止需等回退核实，已经切换后的晚到停止按实际完成记录。

当前完整线上维护只在Linux且`LJM_MANUALS_ONLINE_ENABLED=true`时报告可用。Windows的online夹具只开放草稿能力并拒绝正式动作；本机模式保留原有本地流程。生产开关及PDF状态本轮均未操作，专用投稿审核和PDF交接仍保留独立能力边界。

## 二、事务、回执与空间

新增[线上发布适配](../local-admin/manuals-publication.mjs)，复用现有发布器与保留版本，不引入依赖或后台任务服务。线上事务v2包含操作身份、操作及步骤编号、原输入和状态摘要、前后公开版本及阶段，成功状态保留原初始化记录，并记录最后一次发布归属。

线上事务只保存`previous-source.json`、`previous-state.json`和事务清单，回退引用保留的旧公开版本，不产生`previous-dist`整站副本。新的公开构建仍是一次发布所必需；草稿保存和历史恢复不生成网站构建。本机旧事务保留原有构建备份方式，不能把这次线上优化说成已经改了所有历史备份。

持久操作回执格式未增加字段，便于与现有程序回退规则兼容。既有`GET /api/operations/<编号>`按需追加经过筛选的维护阶段，响应不返回事务私密路径、内部依据或操作者。页面会话存储仅含操作编号、步骤编号及动作，不存完整目录或私密依据。

新增`POST /api/manuals/resolve-operation`，沿用管理员鉴权、同源标记及明确确认。仅当真实事务、状态摘要及公开版本能证明结果时修复待核对回执；无法证明时维持暂停。原请求未开始且没有冲突事务时，登记一个取消屏障，迟到原请求不能再执行。核对不会重放发布；保存或恢复的灾难性落盘异常如无法证明，仍须维护者检查，不能用按钮强行解除。

## 三、共享锁和版本保护

- 说明书完整维护开启后，即使合并功能关闭，也使用原有`/run/lock/laojiumopian-github-deploy.lock`。顺序保持“部署锁→管理写入队列”，相关原档案写入也检查未决说明书事务。
- 部署同步在改写档案生成输入之前检查未决事务。Git部署脚本继续沿用候选`LJM_SITE_DIR`、持锁和停管理写入的原顺序，本轮未改该脚本。
- [共享版本保留](../shared/release-retention.mjs)、[既有发布器](../local-admin/release-deployer.mjs)及既有部署入口增加保护：未决事务、损坏清单或待核对维护回执存在时停止版本整理，不扩大业务资料删除范围。完成事务后才按原至少保留三版规则整理，整理失败不撤销成功发布。
