# 本地档案管理入口使用说明

本地档案管理入口用于在自己的电脑上新建、编辑和发布“老旧默片”网站档案，不需要再通过提示词逐项维护照片和文字。

它只在本机运行，不连接云端，不使用数据库。管理程序不会进入公开网站构建结果。

本说明主要对应默认的本地使用方式。线上安全模式使用同一套管理界面，但数据放在服务器独立私有目录，并由 Cloudflare Access 登录和程序内二次身份核验共同保护；在完成线上部署与回退检查前，本地入口继续保留，不要删除。

## 一、启动和关闭

1. 双击项目根目录的 `启动档案管理.cmd`。
2. 保持弹出的黑色窗口开启。
3. 浏览器会自动打开本地档案管理页面。
4. 使用结束后，关闭黑色窗口即可停止本地管理入口。

本地统一入口使用同一个地址：

- 网站预览：`http://127.0.0.1:4173/`
- 档案管理：`http://127.0.0.1:4173/admin/`

在管理页面点击“查看网站首页”可以进入网站；网站右下角会显示只在本机出现的“返回档案管理”按钮。这个按钮不会写入公开网站文件。

这两个路径都只指向当前电脑，不是互联网网址。原来的 `4174` 预览端口已经停用。

档案管理页面每次打开或刷新后，默认进入一张未保存的“新建藏品”表单，方便直接开始录入。此时不会自动建立草稿、分配永久编号或改动已有档案；如需维护已有记录，点击左侧档案即可打开。

## 二、新建藏品

1. 打开管理页后直接填写默认显示的“新建藏品”表单；从其他页面返回时，也可以点击左侧“新建藏品”。
2. 至少填写入藏日期、藏品分类、题名和显示年代；年代无法判断时填写“年代未知”。
   - “藏品分类”只显示与网站首页一致的七类。信件、老证件等只有一个正式类型的分类会自动对应；老照片、明信片、笔记与笔记本、其他旧物等包含多个正式类型的分类，才会在下方显示“精确类型”。
   - 选择精确类型前，保存和发布按钮会暂时停用，避免误把切换前的类型保存进去。实际保存的仍是正式 `object_type`，例如“明信片”分类下的 `PST` 或 `PCD`。
   - “旧卡片”目前没有正式对象代码，只显示待扩展提示，暂时不能通过管理入口新建或发布；不得为它自行补造代码。
3. 第一次保存草稿时，系统会按 `LJM-YYYYMMDD-TYP-NNN` 自动生成永久编号。
   - 数据规范中的 `item_id`（有时写作“单件唯一编号”）就是这里的“藏品永久编号”，不是另一套编号；管理页面统一显示为“永久编号”。
   - 如果新选择了图片，必须先在“发布图片”中确认它们是经过筛选、压缩并完成必要脱敏的发布副本，草稿才会保存并生成永久编号。
4. 永久编号建立后不会因为后续分类调整而改变。
5. “收藏品编码”第一段是正式对象类型代码，例如明信片为 `PST`、照片明信片为 `PCD`；第二段是基本信息中必填的显示年代，例如 `1979`。之后才是已确定的正式属性短代码。显示年代会去除空格，并把斜线、下划线等分隔符规范为短横线；正式属性代码会去掉第一个短横线及其前缀，例如 `PT-VIEW` 取 `VIEW`。各段用 `_` 连接，同一维度内的多个代码用 `+` 连接。编码不包含永久编号和维度编号，也不需要手工填写，属性修改后会自动更新。
6. “对象专属信息”最上方集中显示全部收藏品编码组成字段，这些字段逐个设为必填。打勾但暂无正式字典代码的维度随后排在其他可选维度前面，并要求至少填写一项。
7. 对象专属信息会随藏品类型自动切换：照片、明信片、日记/笔记、证件使用各自的 21 维；信件、复制件和其他类型只使用通用字段。

如果准备录入同一批次、同一来源的相似藏品，可以打开现有正常档案右上角“更多操作”，选择“以此为模板新建”。系统只复用藏品类型、批次编号、获得方式、来源人／机构、获得地点和省市区；永久编号、入藏日期、题名、显示年代、图片、对象专属信息、公开文字和隐私确认不会复制。新档案只有在本人检查并保存草稿后才会分配编号。

“市级”与“省级、区县”统一放在“更多通用字段 → 地点”中。三个字段提供同一套本地行政区域下拉参照，同时允许录入历史地名。界面不再显示地点代码、人物编号、人数、人物关系、机构编号和证据依据；已有档案中的旧值不会被自动删除。明信片 PC11“通信关系/关联机构”和 PC18“邮票”为选填项，寄发邮局和邮票签发/发行字段不再显示。

参与编码的单值代码字段显示下拉选项，多值代码字段显示可多选的代码列表。日期、原文、批次编号等字段，以及尚未在 `04_代码字典` 定义值表的维度，不会伪装成下拉选项；待定义清单见 `docs/missing-required-code-definitions.md`。

“访客看到的内容”增加可选的“公开修订说明”。只有题名、判断、转录或来源说明发生实质变化时才填写，用一两句话说明公开页面改了什么；普通保存、排版调整和内部操作不需要写。没有填写时，详情页不会显示空的修订区块。

选择“信件（LET）”时，“访客看到的内容”中的现有转录字段会显示为“信件电子文字”。这里按原件逐字录入并保留称呼、段落、换行、落款和日期；无法辨认写 `〔不清〕`，缺失文字写 `□`。私人地址、电话、证件号码和清晰签名等敏感内容不得进入公开文字。该字段仍是既有 `public_view.transcription`，没有另建重复数据。

## 三、上传图片

管理入口只接收已经筛选、压缩并完成必要脱敏的 JPG、PNG 或 WebP 发布副本。

不得上传：

- TIFF、RAW、DNG、PSD 等主档格式。
- 唯一原始扫描件或唯一主档。
- 名称包含 `master`、`original`、`raw`、“主档”或“原始”的文件。
- 尚未遮盖完整证件号码、卡号、私人地址、签名等敏感内容的图片。

选择图片后，可以使用“向前”和“向后”调整网站详情页的显示顺序。

图片显示到编辑区之前会先完成本机预检：

- 检查是否为 JPG、PNG 或 WebP，是否为空或超过 30 MB。
- 检查扩展名与图片格式是否一致，并拦截名称含 `master`、`original`、`raw`、“主档”或“原始”的文件。
- 计算图片的 SHA-256 校验值，与本次选择和 `public-assets/inbox/` 待入站区中的文件比对；内容完全相同的文件不会重复加入。
- 检查结果只在当前编辑页面显示，不会写入档案元数据；通过预检仍不等于完成隐私检查，系统不会自动识别人脸、地址或敏感内容。

每张图片下方可以填写不超过 180 字的“图片说明”。说明应只描述画面中能够确认的内容，不推断人物身份，也不要录入敏感信息。图片说明会跟随排序和替换；没有填写时，公开页会使用题名加“正面、背面或细节图”的中性说明。

已保存的图片可以“替换”或“移除”，但操作会先记录在草稿中，不会马上改动公开网站。只有正式发布和网站构建成功后，旧发布副本才会进入本地“图片回收区”。这不会永久删除图片，也不会影响项目之外的原始档案主文件。

## 四、保存草稿

点击“保存草稿”后：

- 信息保存在本地草稿区。
- 新图片只进入 `public-assets/inbox/永久编号/` 待入站目录。
- 草稿不会复制到网站公开目录。
- 已发布记录的原版本继续留在网站上，直到新修改通过正式发布检查。

编辑档案时，页面底部会持续显示当前保存状态和“保存草稿”按钮。即使正在填写很长的基本信息或专属字段，也不需要滚回页面顶部。进入“隐私与发布”后，底部才会同时出现“检查并发布”；维护概览、草稿中心、图片回收区和历史版本不会显示与当前工作无关的保存、发布按钮。

左侧“草稿中心”集中显示所有尚未正式发布的草稿，并提示仍需处理的缺失项和待回收图片数量。点击“继续编辑”即可回到该藏品。

## 五、发布前预览

“发布前预览”用于在正式发布前查看访客页面的大致效果，包括题名、永久编号、收藏品编码、图片顺序、公开简介、文字记录和标签。

右侧会列出缺失字段、缺少图片、结构不一致和尚未完成的隐私确认。点击某一项会回到对应位置。预览只读取本地草稿，不会把内容公开。

页面上方五个步骤会实时显示当前完成情况：内容齐全时显示“完成”或“可预览”，仍有内容缺失时显示“1 项、2 项”等数量，隐私尚未逐项确认时显示“待确认”。填写或修改字段后提示会立即更新，便于直接找到还需要处理的步骤。

## 六、正式发布

1. 打开“隐私与发布”。
2. 本人逐项完成 13 项检查。
3. 任何一项不能确认时，不要勾选，也不要发布。
4. 全部确认后点击“检查并发布”。

管理入口会依次检查：

- 永久编号和重复情况。
- 核心必填字段。
- Excel 打勾的对象专属必填维度，以及参与收藏品编码的代码字段。
- 收藏品编码只能使用正式代码字典中的值。
- 藏品类型与专属 schema 是否匹配。
- 隐私检查是否全部由用户确认。
- 图片是否全部来自待入站目录。
- 图片路径与永久编号是否一致。
- 网站正式构建是否成功。

只有全部通过后，数据和图片才会进入网站发布层。更新已发布档案时，系统会先在本机保存发布前版本。构建失败时会恢复到发布前状态，草稿继续保留。

正式构建还会自动生成 320、640、1280 和 1920 像素的 WebP 网页副本，让手机和桌面浏览器按需选择。原发布图片不会被修改或替换；撤销档案或移除发布图片后，对应网页副本会在下一次构建时自动重建。

## 七、撤销与恢复档案

左侧“档案管理”下面分为“正常档案”和“已撤销”，默认只显示正常档案；两个子菜单会分别显示数量。切换到“已撤销”后，可以查看撤销记录的基本信息和撤销前保留的发布图片。

撤销一条已发布档案：

1. 打开“正常档案”中的目标记录。
2. 确认该记录没有尚未处理的草稿或未保存修改。
3. 点击右上角“撤销档案”。
4. 填写明确的撤销原因并勾选影响确认，再点击“确认撤销”。

系统会先保存撤销前的数据与图片历史版本，再把该记录和对应发布图片从公开网站构建中撤下。永久编号、正式档案记录和本地待入站图片继续保留；如果构建失败，系统会自动恢复原发布状态。

需要重新维护时，在“已撤销”中点击“恢复为草稿”。恢复不会直接公开，也不会直接编辑撤销追溯记录；它只生成一份隔离草稿。必须重新检查字段、图片和隐私，并再次通过正式构建后，档案才会恢复为正常发布状态。

如果旧撤销记录的图片已经并入另一件主档，恢复按钮会停用并说明原因，避免把已经合并的档案错误拆开。

## 八、图片回收区

- 发布成功后，被移除或替换的旧发布副本进入左侧“图片回收区”。
- 点击“恢复到草稿”后，图片会重新加入对应藏品草稿。
- 恢复不会直接修改公开网站，仍需重新完成检查和正式发布。
- 当前不提供永久清空回收区的按钮，避免误删。

## 九、历史版本

- 每次更新已发布档案时，系统会先保存更新前的数据和图片副本。
- 左侧“历史版本”可以查看这些本地备份。
- 点击“恢复为草稿”后，历史内容只会进入草稿，不会直接覆盖公开网站。
- 如果恢复时已经存在草稿，系统会先自动备份该草稿，避免丢失正在维护的信息。

## 十、维护概览与完整性巡检

左侧“维护概览”用于集中查看日常资料质量，不需要逐条打开档案寻找问题。

- 顶部显示需要关注的正常档案数，以及待补图片说明、研究未完成、备份未达标、复核安排和完整性巡检结果。
- “需要处理的档案”按公开内容、图片说明、研究、权利、备份和复核分组显示待办；点击“打开处理”会直接进入对应档案和填写分区。
- 已撤销记录不计入日常补录数量，只纳入完整性核对，避免和正常档案混在一起。
- “本地完整性巡检”核对正式 JSON、对象类型与专属结构、隐私等级、公开页面、待入站图片、网站原尺寸副本、响应式网页副本和管理端隔离。
- 点击“重新检查”只会重新读取并生成报告，不会自动修改、移动、删除或覆盖任何档案资料和图片。
- 如果巡检发现问题，应先按报告打开对应档案或检查相应发布文件；在原因明确前不要直接整理原始档案主库。
- 维护概览顶部只保留“查看网站首页”，不会显示档案编辑专用的保存和发布操作。
- “更多通用字段 → 利用与保管 → 复盘日期”表示下一次需要复核的日期。建议每次复核完成后安排在未来 12 个月内；未安排、格式异常或日期已到时会进入维护概览，但程序不会自动修改日期。

维护概览中的“需要关注”是资料补充任务，不等同于文件损坏；只有完整性巡检显示失败时，才表示发布结构需要检查。

## 十一、资料查询

左侧“资料查询”用于快速查找和比较结构化资料，不显示也不加载图片。

- 默认查询正常档案；需要查看撤销追溯记录时，主动切换“已撤销”。
- 快速搜索同时匹配永久编号、藏品编码、批次、题名、人物、机构、地点、来源、主题和事件场景；多个关键词需要同时满足。
- 可以继续按访客分类、精确类型、年代、研究状态、证据等级、权利状态和图片结构筛选。
- 图片结构只显示图片数量、人工说明完成数、网页尺寸副本是否齐全和文件名，不请求图片内容。
- 点击查询结果后，右侧只读详情显示身份、时间地点、研究权利、对象专属安全摘要和图片结构。
- “在档案管理中打开”会回到原有编辑流程；查询页面本身不能保存、发布、撤销或删除档案。
- 证件查询投影不返回完整号码、完整私人地址、签名、指纹、主档路径或完整本地绝对路径。
- 每页最多显示 50 条。当前不使用数据库，档案达到数千件且确实出现速度问题后再评估。

“发布前预览”和“隐私与发布”现在还会显示内容质量提示，包括题名过宽、题名重复、公开简介过短或重复、多图说明缺失或完全相同，以及证据未知但公开简介使用确定语气。此类提示只帮助人工复核，不自动改写资料，也不代替正式必填和隐私检查。

## 十二、当前限制

- 撤销记录保持只读，不能直接编辑或重新发布；只能先恢复为草稿并重新完成发布检查。
- 不处理或修改项目之外的原始档案主库。
- 不负责压缩、修图或自动脱敏；这些工作应在上传前完成。
- 不使用 AI 识别人脸、推断身份或猜测模糊内容。
- 不提供永久删除历史版本或清空图片回收区的功能。
- 不使用数据库、云端后台或在线 API，所有管理数据只保存在这台电脑的项目目录中。
