## 怎样使用

1. 如果旧管理服务仍在运行，先保存其他页面的工作，关闭原启动窗口，再双击项目根目录的 `启动档案管理.cmd`。本次开发没有启停日常4173服务。
2. 在 `http://127.0.0.1:4173/manuals/contribute/` 登录；也可以从“我的 → 我的投稿”打开已有说明书草稿。独立4236样例预览不提供账号保存或提交。
3. 分别保存文字、上传图片和保存页序。提供站内阅读副本至少需要一页；只提供官方来源线索时可以没有图片，但必须填写通过安全格式检查的HTTPS网址。
4. 页面下方的“提交审核”会列出仍缺的必要信息。逐项阅读并勾选四项确认，再点击“确认提交审核”。内容不完整或权利情况未确认时，可以继续保留私密草稿。
5. 提交后内容只读，从“我的 → 我的投稿 → 查看投稿进度”进入。页面上方“我的投稿与进度”显示当前状态、站主说明和处理记录；点击“刷新状态”读取最新反馈。
6. 收到“需要补充”时，点击“按要求补充”，回到原编号的草稿。可补充说明、缺页、页序或其他信息；保存后必须重新逐项勾选并点击“确认重新提交补充版本”。没有重新提交前显示“补充中（未重新提交）”。
7. 尚未进入整理的已提交投稿可以“撤回并修改”；已停止处理或暂不采用的投稿，可按页面按钮恢复草稿或修改后重新提交。草稿数量达到20件时，应先处理已有草稿。撤回不会删除旧提交及图片。
8. 展开“已提交版本”，选择一次提交，使用“查看版本信息”或“阅读此版图片”。旧版文字、页序和图片保持只读，不能用查看操作覆盖当前草稿。支持翻页、跳页、适宽与原尺寸阅读。
9. 不再继续的草稿，先保存当前修改，再点击上方“停止这份草稿”。这会释放一个草稿名额，内容和图片仍私密保留，图片继续计入容量。以后从“我的投稿”打开该记录，点击“恢复为草稿”，沿用原编号继续；恢复也遵守20件草稿上限。

“已提交，待核对”代表资料已私密接收，不代表采用或公开。本阶段复用既有“需要补充”和“暂不采用”的私密反馈；没有开放说明书审核通过、转正式档案或加入公开目录。

## 保存、权限与边界

- 沿用现有账号、私密投稿收件区和写入锁，不新增依赖、数据库、服务或后台。说明书信息属于账号投稿业务，不改档案 `core`、`metadata`、`public_view` 或原始主库。
- 四项确认使用独立的说明书确认版本，记录副本、提供范围、隐私和私密处理意愿；不授予额外下载权。每次重新提交均需本人重新勾选，保存、上传或撤回不会代为确认。
- 每次提交保存品牌、型号等全部填写信息、页序、页面身份、印刷页码、说明、图片摘要及本次确认。保留最近20次提交；更早的私密图片仍保留并计入原有容量，不永久删除。
- 操作绑定账号、投稿编号及当前保存版本。最近200次操作留有私密回执，网络结果不明时保持本次请求，重试先查询回执，避免重复提交或重复生成版本。版本冲突时保留本页内容，需读取新版后核对。
- 重试查明该操作没有保存、且投稿已在其他窗口更新时，会解除本次操作锁并提示“刷新状态”；不会反复发送旧版请求。原操作仍在处理中、尚不能确定结果时继续保留回执重试。
- 已提交内容禁止文字和页面写入。旧版图片只允许所属账号读取，并核对提交时的摘要；文件与快照不一致时停止显示。未登录、他人账号、跨站写入和额外权限字段均被拒绝。
- 内部审核备注、操作指纹和内部绑定信息不返回账号端；私密记录和图片不进入公开目录、搜索索引、构建产物或浏览器持久存储。图片响应维持私密、禁止缓存。
- 沿用每日10次提交、20件草稿及5.2容量限制。补充后重新提交也计入每日提交数。暂停接收时可以读取已保存内容和撤回，不能新提交或重新进入补充草稿。
- 普通八图投稿的操作和限制保持原样。说明书不得通过普通匿名查询、普通送审或普通转档案接口绕过专用流程；普通审核接口当前只可给出补充或不采纳反馈，禁止将说明书标为审核通过或转入档案。

新增私密接口为所属账号的 `GET /api/account/manual-submissions/:id`、`POST .../:id/operate`、`GET .../:id/operations/:operation_id` 和 `GET .../:id/versions/:revision/images/:filename`。操作包含提交、恢复补充、撤回和可恢复地停止草稿；均绑定保存版本。图片与文字编辑继续使用原草稿接口，仅允许草稿状态写入。
