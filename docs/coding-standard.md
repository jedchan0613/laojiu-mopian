# 老旧默片编码规范

## 1. 三类不同的编码信息

项目必须明确区分：

1. 永久 `item_id`：只负责确认“这是哪一件对象”。
2. 收藏品编码 `collection_code`：只由当前已确认的核心属性代码自动组合，不包含永久编号。
3. 分类元数据代码：负责记录当前对年代、地点、人物、主题、状态等内容的判断。

三者用途不同，不能互相替代。

**分类判断变化时只修改元数据，不修改永久 `item_id`。**

## 2. 永久编号

正式格式：

```text
LJM-YYYYMMDD-TYP-NNN
```

| 部分 | 含义 |
| --- | --- |
| `LJM` | “老旧默片”项目永久前缀 |
| `YYYYMMDD` | 实物进入本人档案系统的接收或获得日期 |
| `TYP` | `04_代码字典` 中的对象类型代码 |
| `NNN` | 同一接收日期、同一对象类型下从 `001` 开始的三位顺序号 |

例如 `LJM-20260808-PST-001` 表示 2026 年 8 月 8 日接收的明信片类第 001 件对象。

`YYYYMMDD` 不是照片拍摄日期、明信片制作日期、书写日期、邮寄日期、证件签发日期或任何研究判断日期。

## 3. 永久编号原则

1. `item_id` 只表达对象身份。
2. 不把年代、地点、人物、机构、主题、隐私等级或研究结论写入 `item_id`。
3. 永久编号创建后原则上不得修改，也不得复用。
4. 网站 URL、网站图片目录、发布层 JSON 和长期引用统一使用同一个 `item_id`。
5. 编号只使用英文字母、数字和短横线。
6. 不把真实人物姓名写入永久编号。
7. 对象分类判断以后变化时，更新 `object_type` 和对应专属元数据；永久 `item_id` 保持不变。

## 4. 收藏品编码

收藏品编码格式为：

```text
{正式对象类型}_{显示年代}_{去前缀后的代码}[+同维度其他代码][_下一维度代码]
```

例如：

```text
PST_1979_VIEW_COM_UNK
```

规则如下：

1. 收藏品编码不包含永久 `item_id`，永久编号仍单独保存在 `item_id`。
2. 第一段使用 `04_代码字典` 中的正式对象类型代码，例如明信片使用 `PST`、照片明信片使用 `PCD`。
3. 第二段使用基本信息中必填的 `date_display` 显示年代；编码时去除空格，并把斜线、下划线等分隔符规范为短横线。
4. 后续属性段来自 Excel 各对象维度页中 `是否确认唯一属性编码（必填）` 打勾的维度。
5. 除显示年代外，只有能在 `04_代码字典` 找到正式代码的字段才进入属性段；不得根据结构示例补造代码。
6. 正式字典代码去掉第一个短横线及其前缀后进入收藏品编码，例如 `PT-VIEW` 取 `VIEW`、`PF-COM` 取 `COM`。
7. 收藏品编码不写入 `PC01`、`D01` 等维度编号；对象类型、显示年代和各维度按顺序使用 `_` 连接，同一维度多个代码使用 `+` 连接。
8. 所有参与收藏品编码的字段都是必填字段；显示年代放在基本信息中，专属代码字段集中排在对象专属信息页最前面。
9. 收藏品编码由系统自动生成，不能手工填写。
10. 对象类型、显示年代或元数据判断变化时，收藏品编码可以随之重新生成；永久 `item_id` 始终不变。
11. 尚未补齐新必填维度的既有公开记录可以显示当前可生成的部分编码，但下一次正式发布前必须补齐并通过检查。

具体必填维度和代码字段保存在 `site/src/data/standards/collection-code-rules.json`。

## 5. 对象类型代码

当前正式基础来自 Excel `04_代码字典`：

| 代码 | 中文名称 |
| --- | --- |
| `PHO` | 照片正片 |
| `NEG` | 底片 |
| `SLD` | 反转片 |
| `ALB` | 相册 |
| `PCD` | 照片明信片 |
| `PST` | 明信片 |
| `DIA` | 日记 |
| `NTB` | 笔记本 |
| `IDC` | 证件 |
| `CRD` | 商业与服务卡片 |
| `LET` | 信件 |
| `RPR` | 复制件 |
| `OTH` | 其他 |

“旧卡片”访客分类对应正式对象类型 `CRD`，永久编号示例为 `LJM-20260906-CRD-001`；专属元数据使用 `card` schema。

## 6. 分类代码

`PL-*`、`EV-*`、`SU-*`、`PT-*`、`NB-*`、`ID-*` 等代码来自正式代码字典。规则是：

- 代码与原始文字分开保存。
- 多值代码在网站内部使用数组。
- 已有代码进入正式数据后，不修改其含义。
- 需要扩展时新增代码，不借用或重解释旧代码。
- Excel 没有定义的代码不得自行补造。

## 7. FSA 旧规则说明

2026-08-27 本项目经用户明确授权，把正式前缀从 `FSA` 一次性升级为 `LJM`。升级前的开发日志、旧测试快照和 Excel v1 原始示例中的 `FSA` 为历史记录或来源原文，应保留并标注“旧规则”，不能把它们当作现行编号规范。

第一件已发布藏品已从旧编号 `FSA-20260808-PST-001` 迁移为 `LJM-20260808-PST-001`。这是本次规范升级的一次性迁移，不构成日后随意修改永久编号的先例。

## 8. 来源文件中的差异

Excel v1 的字段说明写有“当日连续流水”等旧表述，项目正式实施按用户确认的规则执行：`NNN` 在同一接收日期、同一对象类型下连续编号。Excel 转换出的 JSON 保留来源原文，以便审计；项目执行规则以本文件为准。
