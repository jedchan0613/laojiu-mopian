# 说明书PDF6.2：私密上传与容量验收

日期：2026年11月11日。范围：用户明确要求“执行6.2”。

本地已支持把一份经过筛选的PDF保存到本人说明书草稿、核对上传结果及取消未完成上传。PDF目前只保存私密字节，不运行解析器，不生成页面，不提供文件下载或PDF送审。检查使用虚构账号与合成资料，没有真实资料入站、提交、推送或部署。

## 怎样使用

1. 通过项目根目录的`启动档案管理.cmd`打开日常4173入口。已有旧服务时，先保存其他工作、关闭原启动窗口，再重新启动。本轮未启停日常4173服务。4236独立样例不支持账号保存。
2. 登录后进入“说明书 → 提供说明书”，填写文字；把“希望提供的方式”选为“希望提供站内阅读副本”，点击“保存私密草稿”。不要求此时已具备送审所需的全部信息。
3. 在文字表单下方的“资料保存方式”选择“一份PDF”。只有尚未留存图片、PDF或上传预留的空册才能切换。保留的旧文件不会因切换而被删除；已有文件请继续原方式或另建草稿。
4. 选择一份PDF副本，逐项检查内容并勾选副本确认，点击“上传并私密保存”。保存成功后显示原文件名、大小、保存时间及“尚未解析”；页数显示尚未核实。
5. 连接中断或结果不明时，点击“核对上传回执”。已保存的结果直接找回；仍有预留时，重新选择同一份文件并从头传输。这里没有分块断点续传。需要放弃未完成上传时，使用“取消未完成上传”。
6. 从“我的 → 我的投稿 → 继续编辑”重开原编号。列表区分“PDF已私密保存，尚未解析”和“PDF待上传”。后续6.3、6.4分别开放生成预览和PDF送审，本阶段结束后停止。

已保存但又选中的文件只保留在本页内存中；文件内容、凭据和摘要不写入浏览器持久存储。离开仍有未核对上传或未上传选择的页面时，会提示保留当前工作。

## 本阶段的限制

| 项目 | 实际实现 |
| --- | --- |
| 单份PDF | 最少5字节、最多20 MiB；限定PDF后缀和传输类型，初筛`%PDF-`文件头，服务器重新计算SHA-256并核对精确字节数 |
| 检查含义 | 上述是字节接收检查，不代表PDF可正常打开、无脚本、无附件或已经安全；这些仍待6.3受限解析 |
| 每册留存 | 最多5份不同PDF，旧版本保留；同册相同摘要与大小重新核对后可复用，不跨账号去重 |
| 上传操作记录 | 每册最多200条PDF操作；达到上限拒绝新增，保留原记录 |
| 账号容量 | 沿用200 MiB；图片、PDF、历史副本、回收区、孤立文件、未完成字节和未使用预留统一统计 |
| 服务容量 | 沿用默认10 GiB；新建图片投稿、普通草稿增图、说明书逐页图片与PDF共用全局分配锁和容量检查 |
| 并发传输 | 同账号同时1个，整个服务同时2个，图片与PDF共享名额；文件接收期间不长时间占有全局容量锁 |
| 时间 | 预留15分钟；单次传输最多120秒、空闲30秒。接收中不因预留到期而释放额度 |
| 上线边界 | PDF接口只在本地模式开放；生产模式能力版本为0并返回503。没有增加服务器PDF开关、工具安装或路由变更，线上准备仍属6.6 |

容量统计针对文件载荷。小型JSON记录、锁标记等管理开销不混入既有200 MiB文件额度；草稿、投稿总数和PDF操作数仍各有上限。预留与已写入的临时字节只计一次，文件落盘后不再重复加一份完整预留。

## 保存与故障处理

文件仅进入既有私密投稿目录中的`TG-…/pdf/`；服务器生成文件名，不用上传者文件名拼路径。完整文件不覆盖旧副本。上传进程使用专用租约标记，文件写入和草稿记录切换分开核对。

| 状态或故障 | 处理结果 |
| --- | --- |
| 初始化重试 | 同一操作凭证与相同文件信息返回原回执；同凭证改内容拒绝 |
| 首次查不到操作 | 返回明确的原操作编号与`not_found`，前端再按同一请求初始化 |
| 正在上传 | 冻结本册文字、切换、停止及其他会改版号的动作；仍能查询回执与取消 |
| 字节数、摘要或文件头不符 | 不接纳完整文件；安全关闭写入后清理该次未完成`.part`，旧文件和原草稿不变 |
| 已保存但响应丢失 | 先按操作凭证找回结果并重新核对留存文件，不重新传输或重复留存 |
| 取消与保存竞争 | 保存已生效时返回已保存；不能借取消删除完整文件或历史副本 |
| 过期或中断 | 未使用预留可释放；实际残留继续计量。查询或下一次操作核实无活跃写入后，才清理未完成字节 |
| 服务进程重开 | 根据租约PID核对上次接收；能证明进程已结束时转为中断。进程仍活跃或身份不明时不抢占、不清理 |
| 完整字节已核对、记录写入失败 | 保留完整结果并标“需维护者核对”，阻止继续传输或取消完整结果 |
| 草稿已切换、最终回执写入失败 | 通过草稿的操作绑定及源文件摘要恢复已保存状态 |
| 回执与草稿留存信息不一致 | 草稿与回执入口均显示待核对，停止新增和取消，完整文件继续保留并计量 |
| 外部改写或丢失文件 | 不宣称重试成功；返回需核对信息，账号响应不带私密磁盘路径 |

已完成的PDF、历史副本和图片不会随替换、停止草稿或上传失败自动永久删除。取消清理只针对明确属于本次操作、且已关闭写入的未完成暂存文件。无法确认时保留并说明原因。

## 权限与接口

继续使用既有账号会话、同源防护、专用请求标记、归属核对、上传开关和限流。图片入口拒绝PDF方式，普通投稿入口不能改写说明书；PDF方式的提交审核同时在页面与服务端关闭。

| 接口 | 用途 |
| --- | --- |
| `POST /api/account/manual-drafts/:id/material` | 空册切换图片或PDF，核对草稿版号及操作凭证 |
| `POST /api/account/manual-drafts/:id/pdf/uploads` | 小JSON初始化、绑定文件信息并预留容量 |
| `POST /api/account/manual-drafts/:id/pdf/uploads/:uploadId/content` | 单份PDF二进制流；边写入边计量和计算摘要，不使用图片表单或整段JSON读取 |
| `GET /api/account/manual-drafts/:id/pdf/operations/:operationId` | 查询本人的原上传回执，必要时核实中断 |
| `POST /api/account/manual-drafts/:id/pdf/operations/:operationId/cancel` | 取消该操作的未完成传输；操作自身绑定初始化版号，取消不改写草稿内容 |

回执及详情只返回本人可见的文件名、大小、摘要、时间和状态；不返回内部落盘文件名、绝对路径、进程标记或完整私密记录。没有PDF文件读取路由，不能靠猜图片地址取得PDF。账号业务数据继续与档案`core`、`metadata`及主库分开。

| 既有资料保护 | 502个档案及发布源文件的字节、摘要和时间不变 |

原生解析器没有在6.2执行；19项既有跳过涉及Linux、真实Caddy、POSIX切站等条件，不属于本阶段PDF上传测试。浏览器主体自检后，另外补充“元数据回退／待维护者核对”的服务端和客户端故障检查，并重跑正式构建及全部回归。

浏览器按1280、390、320像素宽度检查，未见整页横向溢出；实测选择、上传、丢响应回执找回、重开预留、取消解锁、其他账号拒绝访问以及“我的投稿”标签。修正了首次未知回执缺操作编号、保存完成仍显示正在核对的进度条，并让待维护者核对的状态重开后直接显示原因。属于浏览器尺寸模拟，没有宣称真机验收。

证据位于Git忽略的`outputs/manuals-pdf-phase6-2/`：`pdf-tests-final.log`、`full-tests-final.log`、`build-final.log`、`browser-checks.json`、三种宽度截图、`public-scan.json`、`baseline.json`及原开发日志字节副本。源代码中没有测试账号或真实文件样例。

首次浏览器测试服务已关闭；手动删除其合成临时目录被自动审批审查以`blocked by policy`拒绝，未提供更具体原因，该目录保留，未改用其他删除方式。最后一次临时测试环境按自身关闭流程结束。没有启停日常4173服务，没有接触真实账号和档案主库。
