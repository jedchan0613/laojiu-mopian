# 档案管理程序

本目录是“老旧默片”的非公开档案管理入口。默认仍采用纯本地模式；只有明确配置 `LJM_ADMIN_MODE=online` 后，才会进入供 Cloudflare Tunnel 使用的线上安全模式。

- `server.mjs` 使用 Node.js 内置模块提供本机服务、草稿保存、图片待入站、发布检查和正式构建，不引入额外依赖。
- `public/` 保存管理界面。
- `drafts/` 在首次保存草稿后自动建立；草稿与正式 `archive-data/` 分开，避免未发布修改覆盖网站当前数据。
- `history/` 在更新已发布档案前保存发布前版本；从历史恢复时只生成草稿，不直接公开。
- `recycle-bin/` 保存发布成功后移出的旧发布副本；图片可以恢复到草稿，不提供永久删除入口。
- 本地和线上模式都只监听 `127.0.0.1`。修改请求必须来自正确的管理页面，并携带管理操作标记。
- 本地模式的网站预览和管理入口共用 `127.0.0.1:4173`：网站位于 `/`，管理入口位于 `/admin/`。线上安全模式另用服务器本机的 `127.0.0.1:4174`，两者不会同时指向同一台设备。
- 网站页面由本地服务临时加入“返回档案管理”按钮，该按钮不写入 `site/dist/`，不会进入公开网站构建。
- 图片只从浏览器进入 `public-assets/inbox/永久编号/`；正式发布通过后才复制到 `site/public/archive/永久编号/`。
- `site/src/data/archive.ts` 在正式发布时根据 `archive-data/` 中满足 `ACT/G/U3` 的记录重新生成。
- 管理页先显示与公开网站相同的七个“藏品分类”；只有一个分类对应多个正式类型时，才显示简短的“精确类型”选择。保存和发布仍使用正式 `object_type`，没有正式对象代码的“旧卡片”保持不可选。
- 省级、市级和区县统一放在“更多通用字段 → 地点”，使用本地行政区域名称参照并允许历史地名；隐藏字段只从录入界面移除，不清理已有档案中的历史值。
- 正式发布必须通过 13 项人工隐私确认、结构检查、图片路径检查和现有 `npm run build`。
- 管理界面提供正常/已撤销档案子菜单、草稿中心、发布前预览、缺失项定位、历史版本和图片回收区。

已发布档案可以安全撤销：系统先保存撤销前历史版本，再把记录与发布图片从公开网站构建中撤下；本地正式记录、待入站图片和永久编号继续保留。撤销记录保持只读，只能先恢复为隔离草稿，再重新完成字段、隐私、图片和正式构建检查，不允许直接重新公开。图片已经并入其他主档的旧撤销记录不能恢复为独立草稿。

已保存图片的移除或替换先写入草稿，只有正式发布和构建成功后，旧发布副本才进入本地回收区；不会永久删除，也不会修改原始档案主文件。

## 线上安全模式

- 线上模式默认使用 `127.0.0.1:4174`，只能由服务器本机上的 Cloudflare Tunnel 转发，不能把端口直接开放到公网。
- 所有管理页面、管理接口和图片预览都会再次核验 Cloudflare Access JWT，包括签名、团队域名、应用 AUD、有效期和管理员邮箱白名单；`/healthz` 只返回服务是否存活，不返回档案内容。
- 线上管理域名只提供 `/admin/` 和管理接口，不通过该域名提供公开网站预览；“查看网站首页”直接前往正式公开域名。
- 线上模式使用独立的持久数据目录保存正式 JSON、草稿、待入站图片、历史版本和回收区，应用版本替换时不能覆盖这些数据。
- 线上发布构建成功后，会在公开版本目录中新建一个只读版本，再用 `live` 软链接一次性切换；旧版本不会自动删除。构建、复制或切换失败时，原网站版本保持不变，管理数据和应用内发布源会恢复到操作前状态。
- 响应会增加禁止搜索引擎收录、禁止嵌入、限制脚本与网络请求来源等浏览器安全规则。
- 为避开 Cloudflare 单次请求上限，线上模式一次保存最多携带约 60 MB 的新图片；单张图片仍不得超过 30 MB。达到提示后先保存草稿，再继续添加下一批，不会降低图片隐私检查要求。
- 配置模板见 `online-admin.env.example`。真实配置必须放在服务器的 `/etc/laojiumopian-admin.env`，不能提交到项目或放入公开网站目录。
- 配置完成后可执行 `node local-admin/server.mjs --check-config` 做只读检查；检查结果不会显示 Access AUD 或邮箱正文。
- 当前实现不增加 npm 依赖，Access 公钥从团队证书地址读取并短时缓存；遇到签名密钥轮换时会自动重新读取。
